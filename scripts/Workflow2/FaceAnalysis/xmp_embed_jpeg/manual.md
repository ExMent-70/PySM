# Внедрение XMP в JPG/JPEG

## 1. Назначение и основные понятия

Скрипт переносит метаданные из внешних файлов `*.xmp` во внутренний XMP-блок
одноимённых изображений JPG/JPEG. После этого Adobe Bridge может показывать
метаданные непосредственно из JPEG.

В начале журнала выводится заголовок
`ВНЕДРЕНИЕ ВНЕШНИХ XMP-МЕТАДАННЫХ В ФАЙЛЫ JPG`.

Изображение не декодируется и не кодируется повторно: скрипт меняет только
служебный сегмент XMP, а сжатые данные изображения копирует побайтно.

Если JPEG уже содержит XMP, выполняется слияние RDF-свойств. Значения внешнего
XMP заменяют совпадающие свойства, а свойства, которых во внешнем файле нет,
сохраняются. Пустое свойство, явно присутствующее во внешнем XMP, также заменяет
соответствующее встроенное значение.

## 2. Параметры запуска

- **Папка изображений** (`image_dir`) — папка с JPG/JPEG.
- **Рекурсивный поиск** (`recursive`) — обрабатывать также вложенные папки.
- **Расположение XMP** (`xmp_source`):
  - `auto` — искать сначала рядом с JPG и в подпапке `XMP`; если найдены оба
    варианта, остановить запуск как неоднозначный;
  - `alongside` — использовать только `имя.xmp` рядом с `имя.jpg`;
  - `subfolder` — использовать только `XMP/имя.xmp`.
- **Резервные копии** (`backup_originals`) — сохранять исходный файл как
  `backup/имя.jpg` в подпапке рядом с исходным изображением. Имя и расширение
  JPEG сохраняются. Существующая резервная копия не перезаписывается.
- **Только проверка** (`dry_run`) — проверить весь пакет без записи файлов.

## 3. Порядок работы

1. Выполняется поиск JPG/JPEG и одноимённых XMP.
2. Все найденные пары полностью проверяются до изменения первого изображения.
3. Проверяется структура JPEG, корректность XML/RDF, итоговый размер XMP и
   отсутствие неподдерживаемых вариантов метаданных.
4. При наличии хотя бы одной ошибки пакет не записывается.
5. Для каждой пары формируется объединённый XMP.
6. Исходный JPEG копируется во временный файл папки `backup`, проверяется и
   только затем атомарно устанавливается как постоянная резервная копия.
7. Новый JPEG сначала записывается во временный файл в той же папке.
8. Проверяется XMP и побайтовая неизменность сжатой части изображения.
9. После успешной проверки временный файл атомарно заменяет исходный JPG.

Внешние XMP после обработки не удаляются.

## 4. Ограничения и безопасность

- Поддерживаются только `.jpg` и `.jpeg`.
- Максимальный размер итогового стандартного XMP — 65 504 байта.
- Extended XMP не поддерживается. Такой файл будет пропущен с ошибкой до
  начала записи пакета.
- Файлы с обнаруженным манифестом Content Credentials (C2PA) не изменяются,
  поскольку сторонняя запись способна нарушить проверку цифрового происхождения.
- Несколько встроенных стандартных XMP-сегментов считаются неоднозначным
  состоянием и не исправляются автоматически.
- Повреждённый JPEG или некорректный XML/XMP не изменяется.
- Резервная копия защищает исходное состояние перед первым успешным запуском.
  При повторных запусках существующая копия сохраняется без перезаписи.
- Файлы внутри папок `backup` и `XMP` не участвуют в поиске исходных изображений даже
  при включённом рекурсивном поиске.

## 5. Рекомендуемый первый запуск

1. Включите `dry_run` и оставьте `backup_originals` включённым.
2. Проверьте итоговые счётчики и отсутствие ошибок.
3. Отключите `dry_run` и повторите запуск.
4. Обновите папку в Adobe Bridge и проверьте ключевые слова и остальные поля.
5. Не удаляйте внешние XMP и резервные копии до завершения проверки.
