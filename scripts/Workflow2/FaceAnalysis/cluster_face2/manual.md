# Универсальный анализатор лиц (v2026.08.20)

## Изменения версии 2026.08.20

- Порядок съёмки загружается из структурированной переменной контекста
  `wf_student_ids_order.{wf_photo_session}_ids_order`.
- Поиск файлов `*_children.txt` удалён; путь к списку ID больше не нужен.
- Проверки формата, уникальности и общего `list_id` сохранены для JSON-массива.

## Изменения версии 2026.06.20

- Идентификация учеников переведена с ФИО на постоянный `student_id` вида
  `A7K3-S001`.
- Порядок съёмки впервые переведён с ФИО на `student_id`.
- `info_faces.json` и `matches_portrait_to_group.json` больше не содержат ФИО.
- Дистанции в JSON округляются до четырёх знаков после запятой.
- Запись JSON выполняется атомарно.

## 1. Назначение
Скрипт `run_cluster_face.py` — это единый инструмент для обработки лиц в проекте. Он управляет полным циклом автоматической обработки: от чистки мусора до распознавания детей на групповых фото.

В зависимости от выбранного **Режима (Mode)**, скрипт выполняет разные задачи, используя общую базу данных.

---

## 2. Режимы работы

### 🛠️ Mode: Tech (Техническая чистка)
**Цель:** Подготовить "сырые" данные к работе, отсеяв явный брак.
*   **Фильтрация:** Удаляет лица, которые нейросеть "увидела" неуверенно, или которые слишком малы (зрители в дальнем углу зала).
*   **Группировка мусора:** Находит повторяющиеся объекты (статуи, плакаты, портреты на стенах) и собирает их в группы `Temp Cluster`, чтобы в Редакторе их можно было удалить одним нажатием.

### 👤 Mode: Face (Сборка портретов)
**Цель:** Собрать одиночные фотографии детей в кластеры и назначить им `student_id`.
*   Работает только с файлами, где в кадре **одно** лицо.
*   Группирует похожие лица одного человека.
*   Автоматически находит список ID фотосессии и назначает их кластерам в хронологическом порядке.
*   Если количество кластеров и ID различается, кластеры сохраняются с `student_id: null` для ручного исправления в Редакторе кластеров.

### 🔍 Mode: Match (Поиск на групповых)
**Цель:** Найти детей на общих фотографиях.
*   Берет сформированные ранее "Портретные кластеры" как эталоны.
*   Сканирует все групповые фото.
*   Если находит совпадение, записывает единый `student_id` и ссылку на портретный кластер.

---

## 3. Описание параметров

### Основные
*   **a_target_dir**: Главная папка с результатами анализа (`Analysis_XXX`). С ней происходят все манипуляции.
*   **a_mode**: Переключатель режима работы (см. выше).

### Универсальный порог (a_sim_threshold)
Этот параметр работает по-разному в разных режимах:

1.  **В режиме Tech:** Это радиус поиска (Epsilon). Значение **0.40**.
    *   Определяет, насколько похожими должны быть "мусорные" лица (статуи), чтобы слипнуться в один кластер.
2.  **В режиме Portraits:** Это радиус поиска (Epsilon). Значение **0.25 - 0.28**.
    *   Определяет строгость отличия одного ребенка от другого. Чем меньше, тем строже (меньше риск смешать детей, но могут раздробиться).
3.  **В режиме Match:** Это порог дистанции (Threshold). Значение **0.45**.
    *   Определяет, насколько лицо на групповом фото должно быть похоже на эталон. Чем меньше, тем строже поиск.

### Для режима Tech (Чистка)
*   **a_clear_min_score**: (0.0-1.0). Порог качества. Рекомендуется `0.6`. Если много мусора — повышайте до `0.65`.
*   **a_clear_min_abs_area**: (px). Минимальная площадь лица. Дефолт `2500` (50x50px).
*   **a_clear_min_rel_area**: (%). Минимальный процент от кадра. `0.001` = 0.1% площади кадра.

### Для режима Portraits (Портреты)
*   **a_algorithm**: `dbscan` (рекомендуется) или `hdbscan`.
*   **a_clear_min_claster_size**: Минимальное количество фото, чтобы считать группу кластером (обычно 3).

### Для режима Match (Поиск)
*   **a_ref_dir**: Заполнять ТОЛЬКО если эталонные портреты лежат в другой папке (например, в прошлой сессии). Обычно оставляют пустым.

## 4. Загрузка порядка идентификаторов (для режима Face)

В режиме `face` скрипт автоматически получает значение `wf_photo_session` и
строит путь к структурированным данным:

```text
wf_student_ids_order.{wf_photo_session}_ids_order
```

Например, для `wf_photo_session = PORTRET` ожидается массив:

```json
{
  "wf_student_ids_order": {
    "PORTRET_ids_order": [
      "A7K3-S001",
      "A7K3-S002",
      "A7K3-S003"
    ]
  }
}
```

Массив обязателен. Пустое значение, дубликаты, смешанные `list_id`, неверный
формат или отсутствие вложенного поля завершают режим с ошибкой. Параметр пути
и отдельный TXT-файл не используются.

Если количество портретных кластеров точно совпало с количеством ID, они
назначаются автоматически по порядку первой фотографии каждого кластера.

Если количество не совпало, результат кластеризации всё равно сохраняется.
Частичное назначение по порядку не выполняется, потому что один объединённый
или лишний кластер мог бы сдвинуть личности всех последующих учеников. Все
нешумовые портретные кластеры получают `student_id: null` и должны быть вручную
исправлены в `cluster_editor` в режиме `face` до запуска режима `matches`.

Типовые исправления:

- для объединённых близнецов создаётся второй кластер, фотографии разделяются,
  и каждому кластеру назначается свой ученик;
- два кластера одного ученика объединяются переносом фотографий в один кластер;
- записи отсутствовавших на съёмке учеников могут остаться неиспользованными.

## 5. Формат результатов

### `info_faces.json`

Идентифицированное лицо содержит единое поле:

```json
{
  "student_id": "A7K3-S001"
}
```

Для группового лица дополнительно сохраняются
`matched_portrait_cluster_label` и `match_distance`. Если совпадения нет,
`student_id` равен `null`.

Поля `child_name` и `matched_child_name` удаляются при запуске любого режима,
включая Cleaning. Значение `student_id: null` сохраняется для кластеров,
которым требуется ручное назначение. Техническое поле `temp_child_name` режима
Cleaning не является ФИО и сохраняется.

### `matches_portrait_to_group.json`

Ключом остаётся номер портретного кластера. Персональная связь хранится в
`student_id`:

```json
{
  "0": {
    "student_id": "A7K3-S001",
    "group_photos": [
      {
        "filename": "IMG_9205.jpg",
        "min_distance": 0.1573,
        "num_faces": 1
      }
    ]
  }
}
```

Все дистанции, записываемые в JSON, округляются до четырёх знаков. Сравнение с
порогом выполняется до округления, поэтому точность идентификации не меняется.

## 6. Типовой сценарий работы (Workflow)

1.  **Запуск Tech:**
    *   Mode: `cleaning`
    *   Sim Threshold: `0.40`
    *   *Действие:* Скрипт пометит мусор. Далее оператор удаляет его в Редакторе (Cleaning).

2.  **Запуск Portraits:**
    *   Mode: `face`
    *   Sim Threshold: `0.25` (Строже, чтобы не смешать детей)
    *   *Действие:* Скрипт соберет портреты и назначит ID из файла фотосессии. Оператор проверяет результат в Редакторе (Face).

3.  **Запуск Match:**
    *   Mode: `matches`
    *   Sim Threshold: `0.45` (Чуть мягче, так как на групповых лица хуже видно)
    *   *Действие:* Скрипт найдет детей на общих фото. Оператор проверяет связи в Редакторе (Matches).
