# История изменений

## 2.2026.11.13

- В `scan_folder_mode` одинаковые номера кадров в `info_faces.json` разрешаются по имени изображения без расширения и без учёта регистра; PSD сопоставляется с одноимённой записью JPG.
- Если среди кандидатов нет единственного точного совпадения имени, изображение пропускается с предупреждением, а остальные файлы продолжают обрабатываться.

## 2.2026.11.07

- В режиме сканирования при отсутствии `info_faces.json` создаются и обновляются XMP с именем изображения и доступными данными контекста.
- При обновлении сохраняются метаданные анализа; повреждённые XMP не перезаписываются. Тип фотографии и данные лиц не предполагаются.

## 2.2026.09.13

- Параметр `student_list_file` стал необязательным.
- При отсутствующем параметре или ненайденном файле списка скрипт выводит предупреждение и продолжает создание XMP без фамилий и имён.
- Без списка сохраняются технические `student_id`, `PySM_<temp_child_name>` и остальные метаданные; при наличии списка сохраняется прежняя строгая проверка ФИО.
- Исправлен полный путь запуска без списка учеников и устранён двойной вывод предупреждений в журнал.
- В начало журнала добавлен заголовок `СОЗДАНИЕ XMP-ФАЙЛОВ`.

## 2.2026.09.12

- Исправлено сопоставление изображений с `info_faces.json` в `scan_folder_mode`: используется последняя цифровая группа основы имени.
- Неоднозначные номера кадров теперь останавливают обработку до записи XMP.
- Служебные папки `XMP` и `backup` исключены из рекурсивного поиска изображений.
- Исправлен URI `GettyImagesGIFT`; старое пространство имён мигрирует при обновлении XMP.
- Исправлена структура Lang Alt для `xmpRights:UsageTerms` и namespace атрибута `xml:lang`.
- Существующий XMP теперь заменяется атомарно без предварительного удаления на Windows.
- Совпадающие пути итоговых XMP блокируются до запуска потоков, а ошибка записи завершает скрипт с ошибкой.
- Непустое значение `faces[].temp_child_name` добавляется как `PySM_<значение>` в `dc:subject` и `lightroom:hierarchicalSubject`.
