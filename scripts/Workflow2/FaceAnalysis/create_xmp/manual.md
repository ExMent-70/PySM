# Руководство по скрипту "Создание/Обновление XMP" (v2.2026.06.20)

## 1. Назначение

Этот скрипт является связующим звеном между этапом AI-анализа изображений и профессиональными программами для каталогизации (Adobe Lightroom, Capture One). Технические данные лиц он читает из `info_faces.json`, а реальные фамилии и имена получает только из `*.list` по `student_id`.

## 2. Логика работы

1.  **Получение путей:** Скрипт принимает пути к рабочим папкам (`--analysis_dir` и `--image_dir`) через аргументы командной строки. Это обеспечивает гибкость и независимость от жесткой структуры проекта.

2.  **Умная загрузка данных:**
    *   Скрипт находит JSON-файл (`info_faces.json`) в указанной папке анализа.
    *   Загружает обязательный `*.list` и строит соответствие `student_id -> Фамилия Имя`.
    *   **Оптимизация:** Файлы с детальной геометрией (`info_*_landmarks.json`) подгружаются **только** если включен параметр `landmark_enable`.
    *   Производит слияние (merge) основных данных и геометрии.

3.  **Обработка изображений:** В многопоточном режиме для каждого фото:
    *   Формирует список ключевых слов (`dc:subject`): имена, локации, эмоции (`PySM_EMOTION_...`), состояние глаз/рта.
    *   Формирует технические коды (`Iptc4xmpCore:SubjectCode`):
        *   `F0_...`, `F1_...`: Данные по каждому лицу.
        *   `IMG_original_shape`: Оригинальные размеры изображения (добавлено в v2026.01.09).
    *   Записывает список персон в `photoshop:TransmissionReference` для портретов.
    *   Записывает ID в существующий массив `Iptc4xmpCore:SubjectCode`.
    *   Записывает имя сессии `wf_session_name` в `photoshop:Headline` (`IPTC - Content - Headline`).
    *   Записывает имя фотосессии `wf_photo_session` в `photoshop:Category` (`IPTC - Content - Category`).

4.  **Атомарное сохранение:** Файлы сначала пишутся во временный буфер, а затем переименовываются.

## 3. Параметры

-   **Папка анализа** (`analysis_dir`):
    -   *Обязательный.* Путь к директории, где лежат JSON-файл с результатами анализа фотографий.

-   **Папка изображений** (`image_dir`):
    -   *Обязательный.* Путь к директории с фотографиями. Именно здесь будут создаваться `.xmp` файлы.

-   **Файл списка учеников** (`student_list_file`):
    -   *Обязательный.* Путь к `*.list` — единственному источнику фамилии и имени.
    -   `*_children.txt` этому скрипту не нужен: порядок съёмки уже обработан кластеризацией.

-   **Количество потоков** (`all_threads`):
    -   Определяет степень параллелизма. По умолчанию (`0`) использует все доступные ядра.

-   **Включить ландмарки** (`landmark_enable`):
    -   Флаг. Если активирован, записывает детальные координаты 106 точек лица. По умолчанию выключено.

## 4. Результат

В указанной `image_dir` создаются `.xmp` файлы, содержащие всю информацию для фильтрации и автоматической обработки фото.

### Пользовательские поля с реальным ФИО

Для каждого разрешённого ученика создаются:

- `PySM_PERSON_Фамилия Имя` в `dc:subject`;
- такое же ключевое слово в `lightroom:hierarchicalSubject`;
- `F0_person:Фамилия Имя` или `F1_person:...` в `Iptc4xmpCore:SubjectCode`;
- `photoshop:TransmissionReference` для портрета.

Значения вида `Кластер_03` больше не используются вместо имени.

### Технический ID в `SubjectCode`

Отдельное пользовательское пространство XMP не создаётся. ID добавляется в
существующий массив `Iptc4xmpCore:SubjectCode`:

```xml
<Iptc4xmpCore:SubjectCode>
  <rdf:Bag>
    <rdf:li>F0:A7K3-S001</rdf:li>
    <rdf:li>F1:A7K3-S002</rdf:li>
  </rdf:Bag>
</Iptc4xmpCore:SubjectCode>
```

Префикс `F0`, `F1` соответствует индексу лица в массиве `faces` исходного
JSON. Записи ID находятся рядом с остальными техническими кодами этого лица.

### Проверка перед записью

До запуска потоков проверяются все XMP, которые реально войдут в текущий
запуск. Неизвестный ID или портретный/matched-кластер без `student_id`
останавливает операцию до создания первого файла. Значение `student_id: null`
допустимо для шума и неопознанных лиц групповых фотографий.

При повторной обработке списки персон и ID заменяются целиком. Поэтому
устаревшие ФИО и идентификаторы не остаются в XMP, а несвязанные пользовательские
поля сохраняются.

## 5. История изменений

### Версия 2.2026.06.22
-   `wf_photo_session` записывается в `photoshop:Category` (`IPTC - Content - Category`).

### Версия 2.2026.06.20
-   ФИО разрешается из `*.list` по `student_id`.
-   `student_id` добавлен в `Iptc4xmpCore:SubjectCode` в формате `F0:A7K3-S001`.
-   Удалена подстановка номера кластера вместо имени.
-   Добавлена предварительная проверка идентичности до записи XMP.
-   Повторный запуск очищает устаревшие имена и ID.

### Версия 2026.02.02
-   **Функционал:** Скрипт работает с единым файлом `info_faces.json`, который содержит информацию о всех фотографиях (портретных и групповых).

### Версия 2026.01.09
-   **Гибкость:** Пути к папкам теперь передаются через аргументы командной строки, а не вычисляются жестко внутри скрипта.
-   **Функционал:** Добавлено сохранение оригинальных размеров изображения (`original_shape`) в секцию `SubjectCode` с префиксом `F0` (как атрибут первого лица/файла) или `IMG`.

### Версия 2026.01.01
-   **Функционал:** Добавлено сохранение состояния рта (`mouth_state`).
-   **Оптимизация:** Внедрен параметр `--landmark_enable` для отключения записи тяжелых геометрических данных.

### Версия 2025.12.24
-   **Архитектура:** Поддержка раздельного хранения данных (отдельные файлы для ландмарок).
