# Руководство по скрипту "Создание/Обновление XMP" (v2.2026.09.13)

## 1. Назначение и основные понятия

Этот скрипт является связующим звеном между этапом AI-анализа изображений и профессиональными программами для каталогизации (Adobe Lightroom, Capture One). Технические данные лиц он читает из `info_faces.json`, а при наличии `*.list` получает из него реальные фамилии и имена по `student_id`.

## 2. Параметры

-   **Папка анализа** (`analysis_dir`):
    -   *Обязательный.* Путь к директории, где лежат JSON-файл с результатами анализа фотографий.

-   **Папка изображений** (`image_dir`):
    -   *Обязательный.* Путь к директории с фотографиями. Именно здесь будут создаваться `.xmp` файлы.

-   **Файл списка учеников** (`student_list_file`):
    -   *Необязательный.* Путь к `*.list` — единственному источнику фамилии и имени.
    -   Если параметр не указан или файл не найден, скрипт выводит предупреждение в лог и продолжает работу без записи ФИО. Технические `student_id` и остальные метаданные сохраняются.
    -   `*_children.txt` этому скрипту не нужен: порядок съёмки уже обработан кластеризацией.

-   **Количество потоков** (`all_threads`):
    -   Определяет степень параллелизма. Значение по умолчанию — `12`; при `0`
        используется количество доступных ядер CPU.

-   **Включить ландмарки** (`landmark_enable`):
    -   Флаг. Если активирован, записывает детальные координаты 106 точек лица. По умолчанию выключено.

-   **Сканировать папку** (`scan_folder_mode`):
    -   Рекурсивно ищет изображения и сопоставляет их с `info_faces.json` по последней непрерывной группе цифр в основе имени.
    -   Например, `TEST3_270363.jpg` сопоставляется с `IMG_270363.jpg` по номеру `270363`.
    -   Папки `XMP` и `backup` при сканировании пропускаются. Если один номер принадлежит нескольким записям JSON, операция останавливается до создания XMP.

-   **Подпапка XMP** (`xmp_subfolder`):
    -   Сохраняет sidecar в подпапке `XMP` рядом с соответствующим изображением.

## 3. Логика работы

1.  **Получение путей:** Скрипт принимает пути к рабочим папкам (`--analysis_dir` и `--image_dir`) через аргументы командной строки. Это обеспечивает гибкость и независимость от жесткой структуры проекта.

2.  **Умная загрузка данных:**
    *   Скрипт находит JSON-файл (`info_faces.json`) в указанной папке анализа.
    *   Если доступен `*.list`, загружает его и строит соответствие `student_id -> Фамилия Имя`. При отсутствии списка предупреждает пользователя и пропускает ФИО.
    *   Файлы с детальной геометрией (`info_*_landmarks.json`) подгружаются только при включённом `landmark_enable`.
    *   Производит слияние основных данных и геометрии.

3.  **Предварительная проверка:** До запуска потоков проверяются `student_id`, неоднозначные номера кадров и совпадающие пути итоговых XMP.

4.  **Обработка изображений:** В многопоточном режиме для каждого фото:
    *   Формирует список ключевых слов (`dc:subject`): имена, локации, эмоции (`PySM_EMOTION_...`), состояние глаз/рта.
    *   Формирует технические коды (`Iptc4xmpCore:SubjectCode`), включая данные каждого лица и оригинальные размеры изображения.
    *   Записывает список персон в `photoshop:TransmissionReference` для портретов.
    *   Записывает ID в существующий массив `Iptc4xmpCore:SubjectCode`.
    *   Записывает `wf_session_name` в `photoshop:Headline`, а `wf_photo_session` — в `photoshop:Category`.
    *   Записывает позу в корректную структуру Lang Alt поля `xmpRights:UsageTerms`.

5.  **Атомарное сохранение:** XMP записывается во временный файл в целевой папке и заменяет прежний файл одной файловой операцией. Ошибка любого рабочего потока завершает запуск с ошибкой.

## 4. Результат

В указанной `image_dir` создаются `.xmp` файлы, содержащие всю информацию для фильтрации и автоматической обработки фото.

### Пользовательские поля с реальным ФИО

Если `*.list` загружен, для каждого разрешённого ученика создаются:

- `PySM_PERSON_Фамилия Имя` в `dc:subject`;
- такое же ключевое слово в `lightroom:hierarchicalSubject`;
- `F0_person:Фамилия Имя` или `F1_person:...` в `Iptc4xmpCore:SubjectCode`;
- `photoshop:TransmissionReference` для портрета.

Значения вида `Кластер_03` больше не используются вместо имени.

Для каждого непустого `faces[].temp_child_name` дополнительно создаётся
техническое ключевое слово `PySM_<temp_child_name>`. Например, значение
`Temp_Cluster_0` записывается как `PySM_Temp_Cluster_0`. Ключевое слово
добавляется одновременно в `dc:subject` и `lightroom:hierarchicalSubject`.

### Технический ID в `SubjectCode`

Отдельное пользовательское пространство XMP не создаётся. ID добавляется в
существующий массив `Iptc4xmpCore:SubjectCode`:

```xml
<Iptc4xmpCore:SubjectCode>
  <rdf:Bag>
    <rdf:li>F0:A7K3-S001</rdf:li>
    <rdf:li>F1:A7K3-S002</rdf:li>
  </rdf:Bag>
</Iptc4xmpCore:SubjectCode>
```

Префикс `F0`, `F1` соответствует индексу лица в массиве `faces` исходного
JSON. Записи ID находятся рядом с остальными техническими кодами этого лица.

### Проверка перед записью

До запуска потоков проверяются все XMP, которые реально войдут в текущий
запуск. Если загружен `*.list`, неизвестный ID останавливает операцию до
создания первого файла. Без списка проверяется только формат технического ID.
Портретный/matched-кластер без `student_id` блокирует запуск в обоих режимах.
Значение `student_id: null` допустимо для шума и неопознанных лиц групповых
фотографий.

Если два исходных изображения приводят к одному пути XMP, операция также
останавливается до записи: параллельная запись в один sidecar запрещена.

При повторной обработке списки персон и ID заменяются целиком. Поэтому
устаревшие ФИО и идентификаторы не остаются в XMP, а несвязанные пользовательские
поля сохраняются.

## 5. История изменений

### Версия 2.2026.09.13
-   Параметр `student_list_file` стал необязательным.
-   Если параметр не указан или файл не найден, в лог выводится предупреждение, а XMP создаются без фамилий и имён.
-   Технические `student_id`, ключевые слова `PySM_<temp_child_name>` и остальные метаданные продолжают записываться без списка учеников.
-   Предупреждения выводятся в журнал однократно.
-   В начале журнала выводится заголовок `СОЗДАНИЕ XMP-ФАЙЛОВ`.

### Версия 2.2026.09.12
-   Исправлено сопоставление в `scan_folder_mode` для имён с цифрами в префиксе, например `TEST3_270363.jpg`.
-   Добавлена блокировка неоднозначных номеров кадров вместо молчаливой подстановки данных последней записи JSON.
-   Папки `XMP` и `backup` исключены из рекурсивного сканирования.
-   `GettyImagesGIFT:OriginalFilename` переведён на поддерживаемый ExifTool URI; старый URI автоматически заменяется при обновлении XMP.
-   Исправлена структура Lang Alt для `xmpRights:UsageTerms` и атомарная замена существующих XMP на Windows.
-   Ошибка рабочего потока теперь возвращает ошибочный код завершения; совпадающие пути итоговых XMP блокируются до записи.
-   Значение `faces[].temp_child_name` добавляется с префиксом `PySM_` в оба списка ключевых слов XMP.

### Версия 2.2026.06.22
-   `wf_photo_session` записывается в `photoshop:Category` (`IPTC - Content - Category`).

### Версия 2.2026.06.20
-   ФИО разрешается из `*.list` по `student_id`.
-   `student_id` добавлен в `Iptc4xmpCore:SubjectCode` в формате `F0:A7K3-S001`.
-   Удалена подстановка номера кластера вместо имени.
-   Добавлена предварительная проверка идентичности до записи XMP.
-   Повторный запуск очищает устаревшие имена и ID.

### Версия 2026.02.02
-   **Функционал:** Скрипт работает с единым файлом `info_faces.json`, который содержит информацию о всех фотографиях (портретных и групповых).

### Версия 2026.01.09
-   **Гибкость:** Пути к папкам теперь передаются через аргументы командной строки, а не вычисляются жестко внутри скрипта.
-   **Функционал:** Добавлено сохранение оригинальных размеров изображения (`original_shape`) в секцию `SubjectCode` с префиксом `F0` (как атрибут первого лица/файла) или `IMG`.

### Версия 2026.01.01
-   **Функционал:** Добавлено сохранение состояния рта (`mouth_state`).
-   **Оптимизация:** Внедрен параметр `--landmark_enable` для отключения записи тяжелых геометрических данных.

### Версия 2025.12.24
-   **Архитектура:** Поддержка раздельного хранения данных (отдельные файлы для ландмарок).
