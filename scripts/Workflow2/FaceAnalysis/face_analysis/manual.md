# Скрипт "Анализ лиц" (v2.2026.06.13)

## 1. Назначение

Скрипт **"Анализ лиц"** является ядром рабочего процесса фотографа. Он выполняет глубокий анализ изображений с использованием нейросетевых моделей. Его задача — найти все лица на подготовленных JPEG-файлах, извлечь их ключевые характеристики (координаты, векторы, атрибуты) и сохранить эту информацию в структурированном виде для последующих этапов (кластеризации, поиска, записи XMP).

## 2. Режимы работы (КРИТИЧЕСКИ ВАЖНО)

Начиная с версии v2.2026.04.27 года, скрипт поддерживает два принципиально разных режима работы, управляемых параметром `a_af_mode`.

### Режим `CREATE` (Создание с нуля)
*   **Когда использовать:** При самом первом прогоне новой фотосессии или когда нужно принудительно пересчитать все файлы.
*   **Как работает:** Скрипт анализирует **каждый** файл в папке. Любые старые данные в выходной папке (JSON-файлы, матрицы векторов `.npy`) **безвозвратно удаляются** и создаются заново. 

### Режим `SYNC` (Умная синхронизация - Smart Sync)
*   **Когда использовать:** Если после первого прогона вы добавили новые фотографии или изменили геометрию (откадрировали) у части уже обработанных фотографий и вам нужно обновить координаты лиц на этих фото, **не сломав** уже проделанную работу по кластеризации и расстановке имен.
*   **Как работает:** 
    1. Скрипт сверяется с файлом `sync_state.json` и находит только те фото, которые были изменены (по размеру или дате). Неизмененные фото мгновенно пропускаются.
    2. Измененные фото анализируются нейросетью.
    3. **Биометрический матчинг:** Скрипт распознает людей на измененном фото "в лицо" (сравнивая их новые векторы со старыми из базы).
    4. **Хирургическое обновление:** Скрипт точечно обновляет *только* геометрические координаты (`bbox`, `landmarks`) в JSON-файлах. Имена, номера кластеров и структура базы данных остаются нетронутыми! Если вы добавили новые фото в папку, они будут аккуратно дописаны в конец базы.

#### Обработка файлов в режиме `SYNC`

В режиме `sync` скрипт сверяет каждый JPEG-файл с `sync_state.json`:

*   **Файл есть в `sync_state.json` и не изменился** — файл пропускается без анализа.
*   **Файл есть в `sync_state.json`, но изменился** — файл анализируется повторно, затем Smart Sync сопоставляет новые лица со старыми по эмбеддингам из `_Embeddings/faces_index.json` и обновляет только координаты, ландмарки и `original_shape`. Если безопасное сопоставление не удалось, файл не помечается как успешно синхронизированный и будет проверен повторно при следующем запуске.
*   **Файла нет в `sync_state.json`** — файл считается новым. Его результаты добавляются в `info_faces.json`, `info_faces_landmarks.json`, `_Embeddings/faces_embeddings.npy` и `_Embeddings/faces_index.json`.
*   **Новый файл успешно прочитан, но лица не найдены** — файл записывается в `sync_state.json`, чтобы не переобрабатываться при каждом следующем запуске, и дополнительно попадает в `skipped_images.json`.

## 3. Логика работы

1.  **Загрузка конфигурации:** Скрипт использует локальный файл `config.toml` для тонкой настройки порогов и провайдеров ускорения (TensorRT, CUDA). Основные параметры теперь вынесены в пользовательский интерфейс.
2.  **Поиск изображений:** Сканирование входной папки на наличие `.jpg` файлов.
3.  **Параллельный анализ:** Обработка выполняется в многопоточном режиме с защитой от перегрузки видеокарты:
    *   **Детекция:** Поиск координат лиц.
    *   **Векторизация:** Вычисление эмбеддингов для каждого лица.
    *   **Атрибуты:** Определение пола, возраста, эмоций и состояния глаз.
4.  **Сохранение результатов:**
    *   `info_faces.json`: Основные данные (координаты, атрибуты).
    *   `info_faces_landmarks.json`: Детальная геометрия лица (106 и 68 точек). Вынесена отдельно для ускорения работы системы.
    *   `_Embeddings/`: Папка с бинарными файлами `.npy` (векторы лиц) и индексом.

## 4. Анализ состояния глаз и Самокалибровка

Скрипт умеет различать 3 состояния глаз: **Closed** (Закрыты), **Squinting** (Прищурены) и **Open** (Открыты).
Поскольку нейросеть по-разному "видит" глаза на крупных портретах и мелких лицах заднего ряда, система автоматически делит лица на 3 категории по ширине (в пикселях): `SMALL`, `MEDIUM`, `LARGE`.

**Самокалибровка:**
При каждом запуске скрипт в фоновом режиме собирает статистику по всем найденным глазам. По завершении работы он генерирует файл `eye_thresholds_recommendations.txt`. В нем содержатся математически выверенные рекомендации по настройке порогов именно под ваше разрешение фотографий. Вы можете скопировать эти значения в `config.toml` (секция `[eye_thresholds]`) для идеальной точности распознавания морганий.

## 5. Параметры запуска (UI)

*   **`a_af_mode`**: Режим работы (`create` или `sync`).
*   **`a_af_model_name`**: Имя набора моделей InsightFace (`buffalo_l` рекомендуется).
*   **`a_af_det_size`**: Внутреннее разрешение детектора (по умолчанию 1280).
*   **`a_af_det_thresh`**: Порог уверенности детектора (0.0 - 1.0).
*   **`a_af_tasks`**: Выбор дополнительных атрибутов для анализа (пол, возраст, эмоции, красота, моргания).
*   **`all_threads`**: Количество потоков обработки (0 — использовать все ядра).

## 6. Подробное описание параметра det_thresh

Параметр `det_thresh` (Detection Threshold) — это **фильтр по уверенности** нейросети.

Когда модель сканирует изображение, она находит сотни потенциальных областей и присваивает им вероятность (score) от **0.0** до **1.0**. `det_thresh` устанавливает границу отсечения.

### Рекомендации для фотографа:
*   **Высокий порог (0.8 - 0.9):** Для портретов. Нет "ложных срабатываний" на фоне, но высокий риск пропустить смазанные лица или профили.
*   **Низкий порог (0.1 - 0.3):** Находятся сложные лица (размытые, мелкие, закрытые рукой). Много "мусора" на фоне, который позже легко отсеивается при кластеризации.
*   **Баланс (0.5 - по умолчанию):** Золотая середина для большинства групповых фото. Если пропускаются лица на задних рядах, понизьте порог до **0.35 - 0.4**.

## 7. История изменений

### Версия 2.2026.06.13
-   **Корректная загрузка модели:** Если модель InsightFace отсутствует локально, автоматическая загрузка с GitHub снова показывает прогресс. При ошибке загрузки скрипт выводит короткое понятное сообщение и завершает работу без traceback.
-   **Smart Sync:** Биометрический матчинг изменённых файлов теперь использует глобальные индексы из `_Embeddings/faces_index.json`, а не локальный `face_index`. Если безопасно сопоставить лица не удалось, файл не помечается как успешно синхронизированный и будет проверен повторно при следующем запуске.
-   **Надёжность сохранения:** JSON-файлы результата и состояние `sync_state.json` сохраняются через временный файл с последующей заменой. В режиме `create` старые итоговые файлы анализа удаляются перед новой сборкой, чтобы не оставлять устаревшие результаты при пустом прогоне.

### Версия 2.2026.04.27
-   **Smart Sync:** Внедрен алгоритм биометрического матчинга лиц (Cosine Similarity) для точечного обновления геометрии откадрированных в Photoshop фотографий без потери привязки к кластерам.
-   **Data-Driven Eye Analysis:** Полностью переработан анализ морганий. Добавлены состояния (прищур), зависимость порогов от масштаба лица и автоматическая генерация статистических рекомендаций.
-   **Улучшенное управление:** Ключевые параметры (модели, размеры, задачи) вынесены в пользовательский интерфейс командной строки.
-   **Надежность хранилища:** Решена проблема "зомби-данных" в бинарных массивах при инкрементальном обновлении. Жестко разделена логика создания с нуля и синхронизации.

### Версия 1.2025.12.24
-   **Архитектура:** Внедрено разделение данных на основные JSON и тяжелые массивы landmarks.
-   **Оптимизация:** Переписан модуль записи результатов (`ResultWriter`).

### Версия 1.2025.06.10
-   **Релиз:** Первая стабильная версия с поддержкой InsightFace buffalo_l и многопоточности.
