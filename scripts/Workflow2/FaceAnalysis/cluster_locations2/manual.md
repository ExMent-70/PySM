# Руководство по скрипту "Кластеризация по локациям/сюжетам" (v2.2026.05.02)

## 1. Назначение

Скрипт **"Кластеризация по локациям"** предназначен для автоматической группировки фотографий на основе схожести их фона (места съемки). Скрипт может работать в двух режимах:

1. **Режим кластеризации (clustering):** Скрипт автоматически находит и группирует похожие локации, не имея о них предварительных знаний.
2. **Режим классификации (classfication):** Скрипт распределяет фотографии по заранее заданным текстовым описаниям локаций (например, "класс с партами", "спортивный зал").

## 2. Логика работы

1. **Требования:** 
   * Для работы скрипта "Кластеризация" необходимо, чтобы предварительно были сгенерированы **маски** — изображения, с которых удалены люди.
   * Для работы скрипта "Классификация" необходимо в параметре `a_cl_location_prompts` задать текстовые описания локаций съемки (сюжетов)

2. **Выбор режима:** Режим работы определяется параметром `mode`.

3. **Вычисление эмбеддингов (с учётом кеша)** 

В любом режиме скрипт использует эмбеддинги. 
Перед вычислением эмбеддингов скрипт проверяет наличие кеша.
Если кеш **актуален**, эмбеддинги загружаются из него.
Если кеш **неактуален**, выполняется:
   * загрузка изображений (масок)
   * обработка изображений с помощью AI моделей
   * получение эмбеддингов

4. **Обработка:**

   * **В режиме кластеризации:** Все полученные эмбеддинги группируются с помощью алгоритма **DBSCAN**. Алгоритм автоматически определяет количество уникальных локаций и присваивает каждой фотографии числовую метку (`0`, `1`, `2`, ...).
   * **В режиме классификации:** Для каждого текстового описания (промпта) с помощью **токенизатора** вычисляется его собственный эмбеддинг. Затем для каждой фотографии находится наиболее семантически близкий текстовый промпт. Фотографии присваивается метка, соответствующая **индексу** этого описания в списке (`0`, `1`, `2`, ...).

5. **Обновление и сохранение результатов:**

   * Скрипт **открывает существующий файл `info_faces.json`**.
   * Для каждой проанализированной фотографии он **добавляет новое поле `location_cluster`** с числовой меткой найденной локации.
   * Обновленный JSON-файл сохраняется.
   * Дополнительно создаются файлы `location_embeddings.npy` и `location_index.json`.


## 3. Параметры запуска

* `mode` - режим работы скрипта (clustering или classfication). По умолчанию выбран режим clustering
* `all_threads` - количество потоков для обработки изображений. По умолчанию - 12. Автоматический выбор - 0.
* `batch_size` Размера пакета одновременно обрабатываемых изображений (по умолчанию 32). 
* `a_cl_data_dir` - путь к папке с исходными данными (файл info_faces.json и папку JPG/Masks).
* `a_cl_config_file` - путь к файлу конфигурации (config.toml).
* `use_originals` - флаг определяющий какие изображения использовать обрабатывать: оригинальные или с масками. ВАЖНО: Для классификации лучше **True**, для кластеризации — **False**.
* `match_threshold` - порог уверенности для режима классификации (0.0-1.0). Если ниже, фото считается неклассифицированным.
* `a_cl_location_prompts` - список текстовых описаний локаций/сюжетов (для режима classification).
* `a_cl_cluster_eps` - параметр 'eps' для DBSCAN (для режима clustering). Определяет, насколько "близко" должны быть эмбеддинги, чтобы считаться одной локацией. Уменьшение этого значения приведет к созданию большего количества более "строгих" кластеров. Значение по умолчанию: `0.13`.
* `a_cl_mask_suffix` - суффикс имен файлов масок.


## 4. Cache система

Для ускорения работы используется система кеширования эмбеддингов.

### 4.1 Image cache

Сохраняется в папке `Cache/image/`

Содержит:
* `embeddings.npy` — матрица эмбеддингов
* `index.json` — соответствие имя файла → индекс
* `meta.json` — метаданные кеша

Image cache пересчитывается если изменилось:
1. Модель
2. Параметры обработки:
   * размер изображения
   * использование оригиналов / масок
   * суффикс маски
3. Файл `sync_state.json`

### 4.2 Text cache

Сохраняется в: `Cache/text/`

Содержит:
* `embeddings.npy`
* `meta.json`

Text cache пересчитывается если изменилось:
* список промптов
* модель
* токенизатор

## 5. Рекомендации по составлению промптов

### Язык промптов

Настоятельно рекомендуется писать промпты на **английском языке** для максимальной точности. Модель CLIP обучалась преимущественно на англоязычных данных и лучше всего понимает нюансы именно этого языка. Русский язык может работать для простых концепций, но для надежного различения сложных сцен английский даст неоспоримое преимущество.

### Примеры промптов:

* **Локация: Класс с партами**

  * (EN): `a photograph of a classroom with school desks`
  * (RU): `фотография класса с партами`

* **Локация: У доски**

  * (EN): `a photograph of a classroom with a blackboard`
  * (RU): `фотография возле школьной доски`

* **Локация: Спортивный зал**

  * (EN): `a photograph of a school gymnasium`
  * (RU): `фотография в спортивном зале`

* **Локация: Школьный двор**

  * (EN): `a photograph of a schoolyard with trees`
  * (RU): `фотография на школьном дворе с деревьями`

* **Локация: Коридор**

  * (EN): `a photograph of a school hallway with lockers`
  * (RU): `фотография в школьном коридоре`

### Как правильно вводить список промптов:

Нужно ли использовать кавычки? **Нет, кавычки вводить не нужно.**

В диалоге PySM для редактирования списка строк каждый промпт вводится с новой строки. Приложение автоматически обработает каждую строку как отдельный элемент списка.

Пример:
Ростовой портрет школьника на фоне карты
Фотография двух школьников сидящих за школьной партой
Групповое фото детей (4 и больше человек) на светлом фоне
