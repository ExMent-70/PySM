# Скрипт "Редактор кластеров" (v2.2026.06.30)

## 1. Назначение

**"Редактор кластеров"** — это профессиональный инструмент для постобработки результатов AI-анализа фотографий. Он предназначен для визуального контроля, ручной коррекции кластеризации, сопоставления лиц и подготовки изображений к выдаче.

Система построена на модульной архитектуре с использованием паттерна **Strategy**, что обеспечивает стабильность работы в различных режимах (Портреты, Локации, Сопоставление, Очистка).

## 2. Параметры запуска

### Основные аргументы

| Параметр | Обязательный | Описание |
| :--- | :---: | :--- |
| `--ce_working_dir` | **ДА** | Полный путь к рабочей папке проекта. Папка должна содержать подпапку `JPG` и файл `info_faces.json`. |
| `--ce_student_list_file` | **ДА** | Путь к `*.list`. В управляемом запуске PySM используется `{wf_psd_path}/{wf_session_name}/{wf_session_name}.list`. Аргумент передаётся и загружается во всех режимах. |
| `--mode` | Нет | Режим работы редактора. Допустимые значения: `face` (по умолчанию), `location`, `matches`, `cleaning`. |
| `--ce_reference_dir`| Нет | Путь к папке с эталонными портретами. Используется только в режиме `matches`. Если не указан, эталоны ищутся в рабочей папке. |

## 3. Основные возможности и Интерфейс

Окно редактора разделено на три функциональные зоны:

1.  **Левая панель (Списки):**
    *   Отображает список кластеров (персон или локаций) с миниатюрами.
    *   Поддерживает Drag & Drop для перемещения файлов между кластерами.
    *   Специальные кластеры: "🗑️ КОРЗИНА", "⚠️ Неопознанные", "99-Noise".

2.  **Центральная панель (Галерея):**
    *   Отображает сетку фотографий выбранного кластера.
    *   Позволяет выделять и перетаскивать фотографии.
    *   Поддерживает множественное выделение и контекстное меню.

3.  **Правая панель (Инспектор):** *[Обновлено]*
    Теперь эта панель разделена на три информационных блока:
    *   **Сверху:** Подробная информация о выбранном файле (Имя, Размеры, Число лиц, Тип, Локация).
    *   **В центре:** Список лиц, найденных на фото.
        *   Клик по лицу выделяет его синей рамкой.
        *   **Двойной клик** открывает полноэкранный просмотр фото с подсветкой этого лица красной рамкой.
        *   В режиме `matches` лица имеют цветные индикаторы (Свой/Чужой/Неизвестный).
			*   🟩 **Зеленый:** Лицо принадлежит текущему выбранному кластеру.
			*   🟦 **Синий:** Лицо опознано, но принадлежит другому человеку.
			*   🟥 **Красный:** Лицо не опознано (из списка ошибок).		
    *   **Снизу:** Детальная информация о выбранном лице (Внутренний ID, AI-атрибуты, данные о сопоставлении).

В нижней строке фильтров расположена кнопка с иконкой выбора файлов. Подсказка кнопки — **«Только фотографии, выбранные пользователями»**. При включении галерея показывает только кадры, шестизначные номера которых присутствуют хотя бы в одном списке `students.*.selected_numbers` файла `photo_selection.json` текущей папки анализа. Повторяющиеся номера разных учеников объединяются. Если файла нет, состав галереи не ограничивается; корректный пустой список скрывает все фотографии.

## 4. Режимы работы

### A. Режим `face` (Редактирование портретов)
*   **Задача:** Сортировка портретных фотографий.
*   **Механизм целостности:** Используется технология **Immutable Index (Face Index)**. Каждому лицу присваивается неизменяемый номер, соответствующий его вектору в базе данных. Это гарантирует, что при превращении группового фото в портрет и обратно, биометрические данные не перепутаются, даже если порядок лиц в списке изменится.
*   **Идентификация:** Кластеру назначается ученик из `*.list`. Свободный ввод ФИО отключён. Один `student_id` нельзя назначить нескольким портретным кластерам.
*   **«Назначить/сменить ученика»:** связывает существующий кластер с записью `*.list`; команда не переименовывает ФИО.
*   **«Создать кластер для ученика»:** создаёт пустой целевой кластер для свободной записи `*.list`. Это позволяет, например, разделить ошибочно объединённые фотографии близнецов.
*   **Исправление лишнего кластера:** фотографии переносятся в правильный кластер. После переноса последней фотографии пустой лишний кластер исчезает.
*   **Сохранение:** каждый существующий портретный кластер должен получить один `student_id`, но использовать все записи `*.list` не требуется — отсутствующий на съёмке ученик может остаться неназначенным.

### B. Режим `location` (Редактирование локаций)
*   **Задача:** Группировка по местам съемки.
*   **Особенности:** Позволяет назначать "Обложку" для локации через контекстное меню фото.
*   **Контекст PySM:** при загрузке и сохранении обложек используется переменная `sys_location_name.{wf_photo_session}`. Например, для фотосессии `SCHOOL` ключ будет `sys_location_name.SCHOOL`.

### C. Режим `matches` (Сопоставление)
*   **Задача:** Поиск и подтверждение присутствия конкретного человека на групповых фото.
*   **Интерфейс:**
    *   Слева: Эталонные портреты.
    *   Центр: Групповые фото, где найден этот человек (отсортированы по имени файла).
    *   Справа: в списке лиц выбранного фото неопознанные лица показываются первыми для кластера "Неопознанные", а лицо текущего портретного кластера — первым для обычных портретных кластеров.
*   **Ручное сопоставление:** Перетаскивание фото из кластера "Неопознанные" на портрет эталона открывает диалог выбора лица (показываются только неопознанные кандидаты).
*   **Сохранение:** Генерирует файлы `matches_portrait_to_group.json` (списки найденных) и `error_matches.json` (ошибки). Файлы создаются гарантированно, даже если списки пусты.
*   **Формат данных:** В `info_faces.json` и `matches_portrait_to_group.json` сохраняется только `student_id`. ФИО для интерфейса, экспорта и водяных знаков каждый раз получается из `*.list`.

### D. Режим `cleaning` (Техническая чистка)
*   **Задача:** Удаление брака и мусорных кадров.
*   **Важно:** Кнопка "Удалить мусор и Сохранить" выполняет **физическое удаление** информации о помеченных лицах из базы данных и пересборку файла векторов (`.npy`).

## 5. Экспорт изображений

Модуль экспорта — это мощный инструмент для пакетной цветокоррекции и брендирования.

### Интерфейс настроек
Диалог настроек разделен на вкладки (Аккордеон):

#### Вкладка 1: 🎨 Коррекция изображения
Инструменты аналогичны RAW-конвертерам (например, Capture One):
*   **Базовые:** Яркость, Контраст, Насыщенность, Резкость.
*   **Баланс белого:**
    *   **Температура:** Холодный (-100) <-> Теплый (+100).
    *   **Оттенок:** Зеленый (-50) <-> Маджента (+50).
*   **HDR / Уровни:**
    *   **Точка черного:** Позволяет усилить тени или сделать их матовыми.
    *   **Точка белого:** Управление пересветами.
*   *Двойной клик по любому слайдеру сбрасывает его в значение по умолчанию.*

#### Вкладка 2: 📤 Параметры экспорта
*   **Формат:** Настройка DPI, Качества JPEG, Ресайз (Ширина/Высота) с сохранением пропорций.
*   **Водяные знаки (Watermarks):**
    *   **Чекбокс "Включить при экспорте":** Главный переключатель. Если выключен, фото сохраняются чистыми.
    *   **Кнопка "👁 Показать":** Включает отображение водяных знаков в окне превью для настройки.
    *   **Гибкая настройка:**
        *   Прозрачность защитных полос и текста.
        *   Уровень затемнения лиц (маска).
        *   Отступы маски от границ лица (W/H коэффициенты).
        *   Кастомный текст на полосах.

### Производительность
Экспорт использует **Multiprocessing** с числом процессов, заданным параметром `--all_threads` и ограниченным числом доступных CPU. Одновременно может выполняться только один экспорт.

## 6. Технические детали и Архитектура

1.  **Shared Image Processing:** Логика цветокоррекции и генерации водяных знаков вынесена в отдельное ядро (`image_processing.py`). Это гарантирует 100% совпадение картинки в окне превью и в итоговом файле.
2.  **Безопасность данных:**
    *   При сохранении создаются бэкапы JSON файлов (`.json.bak`).
    *   Векторы лиц (`_Embeddings/*.npy`) пересобираются только в режиме `cleaning`, в остальных режимах они доступны только для чтения или перелинковки через индексы.
3.  **Контекст:** Все настройки экспорта (цвета, размеры, тексты) сохраняются в контекст приложения (`pysm_context`) и восстанавливаются при следующем запуске.
4.  **Общий кэш изображений:** Галерея, обложки кластеров, миниатюры лиц, диалог выбора лица, viewer и экспортное превью используют `pysm_lib.pysm_image_cache`. Декодирование выполняется вне GUI-потока, устаревшие и ожидающие запросы отменяются.
5.  **Согласованное сохранение:** В режиме `cleaning` JSON, NPY и индекс эмбеддингов сначала формируются во временных файлах и заменяются одним bundle-коммитом. В режиме `matches` основной и производные JSON относятся к одной версии сохранения.
6.  **Ограничение ресурсов:** RAM-бюджет и число потоков декодирования выбираются по доступной памяти. Дисковый кэш ограничен и удаляет давно не использовавшиеся производные изображения.
7.  **Безопасный экспорт:** Итоговый JPEG публикуется атомарной заменой временного файла. Каталоги учеников включают `student_id`, поэтому однофамильцы не объединяются.
