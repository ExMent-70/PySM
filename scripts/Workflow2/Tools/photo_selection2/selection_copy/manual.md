# Копирование выбранных фотографий

## Назначение и основные понятия

Скрипт сразу выполняет копирование или перемещение без отдельного окна, сохраняя правила выбора
файлов и подпапок базового `photo_selection`. Обработка существующих файлов
задаётся параметром `--on_conflict`, операция — параметром `--mode`.
Читает выбор учеников из `photo_selection.json` и учитывает выбор фотографа —
файлы с префиксом `PH_` в начале имени, без учёта регистра.

Нужны только `info_faces.json` и `photo_selection.json` в папке анализа.
Скрипт объединяет выбранные номера всех учеников и учитывает файлы `PH_`.
Фото идентифицируются по шестизначному номеру. Список `*.list`, распознавание лиц,
`matches_portrait_to_group.json` и `photo_assignments.json` для копирования не нужны.

Результат — файлы в папке назначения. При `copy` оригиналы сохраняются, при `move`
успешно перенесённые оригиналы удаляются. Оба JSON выбора и назначений остаются неизменными.

## Параметры запуска

| Параметр | Назначение | Значение по умолчанию в PySM |
|---|---|---|
| `--analysis_dir` | Папка с photo_selection.json и info_faces.json: выбранные номера и локации. Обязателен. | `{wf_session_path}/{wf_session_name}/Output/Analysis_{wf_photo_session}` |
| `--source_dir` | Исходная папка с изображениями для поиска и копирования выбранных номеров. Обязателен. | `{wf_session_path}/{wf_session_name}/Output/Analysis_{wf_photo_session}/JPG` |
| `--dest_dir` | Целевая папка для выбранных RAW или готовых фотографий; подпапки создаются по локациям. Обязателен. | `{wf_psd_path}/{wf_session_name}/Альбом/Фото/{wf_photo_session}` |
| `--exclude_dirs` | Имена подпапок, исключаемых при поиске и копировании на любой глубине. Необязателен. | `Masks` |
| `--on_conflict` | Действие при совпадении имени: `skip`, `overwrite` или `rename`. Необязателен. | `skip` |
| `--mode` | `copy` — копировать с сохранением оригиналов; `move` — переместить. Необязателен. | `copy` |

При прямом запуске обязательные параметры передаются явно. В PySM шаблоны
подставляются из контекста. Удалены параметры `--student_list_file`, `--session_name`,
`--photo_session`, `--title` и `--message`: если они были добавлены в экземпляр
этого скрипта, уберите их из запуска. Принадлежность выбора классу и фотосессии
проверяют импорт и создание плана; для копирования укажите нужную папку анализа.

## Быстрый старт

При переносе сохраняйте папку `photo_selection2` целиком, включая `_common`.
Запуск не зависит от текущей рабочей папки. Без API PySM прогресс и пути выводятся
в терминал; в PySM итоговый отчёт содержит ссылки на исходную и целевую папки.
Ошибка оформления отчёта не меняет результат уже выполненной операции.

1. Сохраните выбор скриптом `selection_import`.
2. Укажите папки источника и назначения для текущего прохода RAW или JPG. Для перемещения задайте `--mode move`; по умолчанию файлы копируются.
3. Запустите скрипт — дополнительных нажатий и подтверждений нет.
4. Дождитесь завершения и проверьте итоговый отчёт в журнале PySM.

## Прогресс и результат

В главном окне PySM отображается прогресс операции. Во время проверки входных
данных и повторного сканирования показывается неопределённый прогресс; при
копировании — число обработанных файлов из общего количества и текущее имя файла.
Пропущенные файлы также учитываются в прогрессе.

Итоговый отчёт содержит количество скопированных или перемещённых и пропущенных файлов,
предупреждения и ошибки. Если исходных файлов для копирования нет, это явно
сообщается. Скрипт не создаёт окна, диалоги, JPG-предпросмотр или кэш миниатюр.
Для просмотра фотографий и персональных назначений используется скрипт №3.

Код завершения `0` означает успешное выполнение без блокирующих ошибок.
Код `1` означает ошибку проверки, записи или удаления оригинала либо изменение
выбора во время операции. Уже скопированные файлы при частичной ошибке остаются;
после устранения причины можно повторить запуск. Вне PySM прогресс выводится
в терминал. Прогресс закрывается и при ошибке.

## Правила копирования

Источники и назначение сканируются рекурсивно. Исключаемые имена папок действуют
на любой глубине; по умолчанию исключается `Masks`. `CaptureOne` по умолчанию
не исключается. Копируются все найденные исходные файлы выбранного кадра,
включая XMP и сопоставленные настройки Capture One, без фильтра расширений.

Название подпапки берётся из `location_name` в `info_faces.json`. Если локация
не задана либо выбранный номер отсутствует в анализе, используется `unknown`.
Вложенная структура сохраняется. Если первая подпапка источника уже называется
как локация, её имя не добавляется повторно.

Пример: `source/portrait/IMG_901256.jpg` → `dest/portrait/IMG_901256.jpg`.
Файл `PH_IMG_901270.jpg` добавляет фотографический выбор всему логическому кадру.
Префикс учитывается как в источнике, так и в уже заполненном назначении.

Один физический файл копируется один раз независимо от количества выбравших учеников.
Если путь назначения уже занят, применяется `--on_conflict`:

- `skip` (по умолчанию) — пропустить файл, оставив существующий без изменений.
- `overwrite` — заменить существующий файл новой копией.
- `rename` — сохранить новый файл под первым свободным именем с числовым
  суффиксом перед расширением: `photo (1).jpg`, `photo (2).jpg` и так далее.

Содержимое существующего файла не сравнивается. При копировании с `on_conflict=rename`
повторный запуск создаёт дополнительную копию даже для идентичных файлов; при
`overwrite` файл записывается заново. Для XMP и настроек Capture One режим
применяется отдельно к каждому физическому файлу. При совпадении исходного и
целевого физического файла он пропускается в любом режиме.

Замена выполняется после успешной записи временной копии. Если запись или
публикация копии не удалась, существующий файл сохраняется, ошибка выводится
в журнал, а скрипт продолжает обработку остальных файлов и возвращает код `1`.
Обычное совпадение имени, обработанное выбранным режимом, ошибкой не является.

### Режим перемещения

При `--mode move` каждый выбранный файл сначала записывается во временный файл
в назначении. После успешной публикации удаляется оригинал. Этот способ работает
и между разными дисками. Пустые исходные папки не удаляются.

- `skip`: существующий целевой файл и оригинал остаются без изменений.
- `overwrite`: целевой файл заменяется, затем удаляется оригинал.
- `rename`: новый файл получает свободное имя с суффиксом, затем удаляется оригинал.

Если запись или публикация не удалась, оригинал не удаляется. Если удалить его
не удалось либо обнаружено изменение оригинала во время операции, сохраняются
обе версии и выводится ошибка. В отчёте отдельно указано число файлов,
скопированных без удаления оригинала; они не считаются успешно перемещёнными.
Остальные файлы продолжают обрабатываться, итоговый код — `1`.

При `--mode copy` исходные файлы не удаляются. Уже выполненные операции при
частичной ошибке не откатываются. После устранения причины скрипт можно запустить
повторно; оставшиеся исходные файлы обрабатываются с выбранным `on_conflict`.

## Ошибки и повторный запуск

Некорректные JSON, записи выбора, неоднозначные номера и небезопасные локации
блокируют операцию. Для выбранного номера без физического файла выводится
предупреждение. Проверки учеников и распознавания относятся к созданию плана.
После RAW-прохода отсутствие готовых JPG и плана не является ошибкой копирования.

Удаление номера из выбора не удаляет прежнюю копию. Оставшийся файл `PH_` продолжает
считаться выбором фотографа. Автоматической очистки папок нет.

После финального копирования выполните `selection_assignments`. Промежуточное
копирование RAW в `Selects` ещё не подготавливает фотографии для вёрстки.

## Последовательности RAW и JPG

Для всех этапов одной фотосессии используйте одинаковый `analysis_dir`.
В импорте и создании плана также должны совпадать `student_list_file`,
`session_name` и `photo_session`.

### RAW

1. Запустите `selection_import` и сохраните выбор.
2. Запустите `selection_copy` с папками:

   ```text
   --source_dir: {wf_session_path}/{wf_session_name}/Capture/{wf_photo_session}
   --dest_dir: {wf_session_path}/{wf_session_name}/Selects/{wf_photo_session}
   ```

3. Обработайте фотографии в Capture One и экспортируйте их в:

   ```text
   {wf_session_path}/{wf_session_name}/Output/Альбом/Фото/{wf_photo_session}
   ```

4. Повторно запустите `selection_copy`:

   ```text
   --source_dir: {wf_session_path}/{wf_session_name}/Output/Альбом/Фото/{wf_photo_session}
   --dest_dir: {wf_psd_path}/{wf_session_name}/Альбом/Фото/{wf_photo_session}
   ```

5. Запустите `selection_assignments` с папками из шага 4 и создайте план вёрстки.

### JPG

1. Запустите `selection_import` и сохраните выбор.
2. Запустите `selection_copy`:

   ```text
   --source_dir: {wf_session_path}/{wf_session_name}/Output/Analysis_{wf_photo_session}/JPG
   --dest_dir: {wf_psd_path}/{wf_session_name}/Альбом/Фото/{wf_photo_session}
   ```

3. Запустите `selection_assignments` с теми же папками и создайте план вёрстки.

Для финального копирования и плана должны совпадать также `exclude_dirs`.
Пример списка класса: `{wf_psd_path}/{wf_session_name}/{wf_session_name}.list`.
Папка анализа: `{wf_session_path}/{wf_session_name}/Output/Analysis_{wf_photo_session}`.

Если нужно изменить выбор, повторно откройте импорт, выполните копирование
и заново создайте план. В уже открытом окне нажмите «Обновить список».
Генератор альбомов запускается после успешного завершения этих этапов.
