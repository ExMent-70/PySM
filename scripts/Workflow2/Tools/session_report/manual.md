# Руководство по скрипту "Генератор отчета" (v2026.08.27)

## 1. Назначение

Скрипт **"Генератор отчета"** предназначен для визуализации текущего состояния файловой системы проекта. Он сканирует ключевые папки (RAW, Capture One, Photoshop) и формирует интерактивный HTML-отчет со ссылками на ресурсы.

Скрипт поддерживает три визуальных стиля (шаблона) и режимы фильтрации данных.

## 2. Логика работы

Скрипт автоматически считывает глобальные переменные процесса (например, `wf_session_path`, `wf_photo_session`) и выполняет следующие действия. Сбор ресурсов вынесен в общий модуль, который также используется вкладкой «Ресурсы заказа» Project CRM, поэтому оба интерфейса показывают один и тот же состав файлов.

1.  **Сканирование ресурсов:**
    *   Проверяет наличие корневых папок (RAW, PSD, Шаблоны).
    *   Анализирует структуру сессии Capture One.
    *   Ищет результаты работы AI (папки `Analysis_*`, файлы JSON, маски, сгенерированные отчеты).
    *   Проверяет наличие XMP-файлов (метаданных) в папках съемки.
    *   Не показывает отдельный ресурс порядка съёмки: эти данные хранятся в контексте PySM, а не в файле.

2.  **Генерация HTML:**
    *   На основе собранных данных формирует HTML-код.
    *   Использует цветовую тему PySM для оформления (поддержка темной и светлой темы).
    *   Вставляет векторные иконки для наглядности.

3.  **Вывод:** Результат выводится непосредственно в консоль PySM в виде HTML-блока.

## 3. Параметры запуска

### Основные настройки

*   **`template` (Шаблон отчета):**
    *   `standard` (по умолчанию): Выводит данные в виде **иерархического дерева** (списка). Удобен для компактного просмотра структуры папок. Использует чередование цветов строк ("зебра").
    *   `dashboard`: Выводит данные в виде **блочной сетки (таблицы)**. Этот режим удобен для визуального контроля статуса обработки (например, наличие XMP, масок и отчетов сразу видно в соответствующих ячейках).
    *   `workflow`: Формирует последовательный отчёт **«Этапы обработки»**. Он показывает выполненные, невыполненные и требующие внимания стадии подготовки заказа, обработки каждой фотосессии и выпуска готовых материалов.

*   **`scope` (Объем данных):**
    *   `current` (по умолчанию): Отчет формируется **только** для текущей активной фотосессии (переменная `wf_photo_session`). Остальные папки `Analysis_*` игнорируются.
    *   `full`: Скрипт сканирует папку `Output` и выводит информацию по **всем** найденным фотосессиям в рамках текущего проекта.

Если для режима `current` не задана переменная `wf_photo_session`, скрипт
завершается с понятным сообщением. Он не переходит молча к полному отчёту.

### Настройки интерфейса

*   **`icon_size_tree`**: Размер иконок для шаблона `standard` (в пикселях). Рекомендуемое значение: `20` - `24`.
*   **`icon_size_dashboard`**: Размер иконок для шаблона `dashboard` (в пикселях). Рекомендуемое значение: `32` - `48`.

## 4. Особенности отображения

### Шаблон "Standard" (Дерево)
Отображает три основных блока:
1.  **Глобальные ресурсы:** Ссылки на корни дисков и каталоги.
2.  **Сессия Capture One:** Древовидная структура папок `Capture`, `Output`, `Selects` и их содержимое.
3.  **Работа с альбомами:** Структура PSD файлов и шаблонов.

### Шаблон "Dashboard" (Плитка)
Ориентирован на контроль выполнения этапов.
*   **Уровень Проекта:** Верхняя таблица со ссылками на основные папки сессии.
*   **Блоки Сессий:** Для каждой фотосессии создается отдельная панель:
    *   **Заголовок:** Имя сессии. Если в папке `Capture` найдены `.xmp` файлы, появится зеленый индикатор **[XMP найдены]**.
    *   **Таблица ресурсов:** Ссылки на `AI Analysis`, `JPG`, маски
        `Masks/Cutout`, `photo_selection.json`, `photo_assignments.json`,
        остальные JSON-файлы и итоговый отчёт.
    *   **Цветовая индикация:**
        *   **Зеленый:** Ресурс существует.
        *   **Красный:** Критический ресурс отсутствует.
        *   **Серый:** Некритичный ресурс отсутствует.

### Шаблон "Workflow" (Этапы обработки)

Отчёт построен по производственному процессу, а не по структуре каталогов:

1. **Подготовка заказа** — рабочие папки, Capture One-сессия, список,
   договор и эталонная фотосессия.
2. **Обработка фотосессий** — количество RAW, JPG, масок и XMP, маркеры
   `var_claster_run`, JSON-результаты, HTML-отчёт и подготовка фотографий для
   альбома. Для папок альбома отдельно проверяются PSD/JPG и наличие XMP во
   вложенных папках.
3. **Общие результаты заказа** — документы InDesign, готовые страницы и JPG
   для передачи заказчику из папки `Выпускникам` в корне заказа.

Все доступные ресурсы показаны ссылками с соответствующими иконками. Иконки
ресурсов незавершённых этапов окрашиваются в серый цвет, а этапов с
предупреждениями — в красный. Отсутствие ресурса не прерывает построение
отчёта, а отмечается как незавершённый этап или предупреждение.

Каждая строка этапа содержит индикатор готовности, компактную иконку ресурса и
описание результата. Существующий ресурс открывается щелчком по иконке, а его
название и полный путь показываются во всплывающей подсказке. Отдельная колонка
«Выполнено / Не выполнено» не используется.

Перед таблицей папок альбома отчёт отдельно сообщает, скопированы ли фотографии
для вёрстки. Иконка этой строки открывает общую папку
`Альбом/Фото/<фотосессия>`, если она существует. Заголовок «Шаблоны и документы
InDesign» открывает родительскую папку `_ШАБЛОНЫ_`.

В полном отчёте фотосессия определяется по любому сохранившемуся рабочему
ресурсу: папке `Capture/<имя>`, `Output/Analysis_<имя>`,
`Альбом/Фото/<имя>` или записи `<имя>` в `var_claster_run`. Поэтому после
перемещения исходных RAW из `Capture` уже выполненные этапы конвертации,
анализа, отбора и вёрстки остаются видимыми.
