# Каталогизатор шаблонов InDesign (v2.2026.09.06)

## 1. Назначение

Каталогизатор шаблонов InDesign используется для ведения каталога IDML-шаблонов и IDMS-сниппетов. Скрипт помогает выбрать шаблон, настроить его мастер-страницы, сопоставить плейсхолдеры с папками фотографий и сохранить результат в переменную контекста PySM для последующей генерации разворотов.

Каталогизатор не создает итоговый альбом. Его задача - подготовить корректное описание шаблона: какой IDML-файл использовать, какая мастер-страница активна, какие графические и текстовые плейсхолдеры есть в шаблоне, какие IDMS-сниппеты подключены и как они должны быть применены.

## 2. Основные возможности

- Ведение каталога IDML-шаблонов с категориями и вложенными категориями.
- Просмотр превью шаблонов и мастер-страниц.
- Создание, редактирование, копирование и удаление карточек шаблонов.
- Настройка активной мастер-страницы шаблона.
- Автоматическое чтение графических и текстовых плейсхолдеров из IDML.
- Настройка сопоставления графических плейсхолдеров с папками фотографий.
- Настройка переопределения графических и текстовых плейсхолдеров на обычных разворотах.
- Настройка параметров позиционирования фотографий: `eye_line` и `face_scale`.
- Ведение отдельного каталога IDMS-сниппетов.
- Массовое обновление карточек категории из актуальных IDMS с сохранением
  пользовательских тегов.
- Подключение IDMS-сниппетов к мастер-страницам шаблона.
- Выбор слоя для вставки сниппета: конкретный слой шаблона или исходные слои сниппета.
- Управление порядком, видимостью и заменой подключенных сниппетов.
- Формирование составного превью мастер-страницы с подключенными сниппетами.
- Назначение тегов шаблонам и сниппетам.
- Фильтрация шаблонов и сниппетов по тегам.
- Сохранение пресетов для списка сниппетов и параметров плейсхолдеров.

## 3. Параметры запуска

| Параметр | Обязателен | Назначение | Значение по умолчанию / пример |
| --- | --- | --- | --- |
| `idsgn_catalog` | Нет | Путь к файлу каталога шаблонов. Если файл отсутствует, он будет создан. Шаблоны, превью и служебные файлы обычно хранятся рядом с каталогом или во вложенных папках относительно него. | `{wf_idsgn_catalog}` или `D:\template\ФОТОСЕССИИ\2026\catalog.template` |
| `idsgn_snippets_catalog` | Нет | Путь к каталогу IDMS-сниппетов. | Если не указан, используется `snippets_catalog.json` рядом с основным каталогом шаблонов. |
| `idsgn_template_var` | Нет | Имя переменной контекста PySM, куда сохраняется выбранный и настроенный шаблон. Поддерживается точечная нотация. | `wf_indsgn_template.default` |
| `idsgn_msg` | Нет | Текст для заголовка окна. Удобен, если один и тот же скрипт используется в разных сценариях. | `Каталогизатор шаблонов InDesign` |
| `idsgn_win_state_var` | Нет | Имя переменной контекста PySM для сохранения состояния окна, сплиттеров и режима сортировки шаблонов. | `win_state.idsgn_catalog` |

В управляемом запуске список доступных папок фотографий читается из
структурированной переменной `sys_location_name.<wf_photo_session>`, например
`sys_location_name.SCHOOL`. Если `wf_photo_session` не задана, используется
корневая переменная `sys_location_name`.

## 4. Рабочий процесс

1. Пользователь открывает Каталогизатор.
2. В левой панели выбирает категорию шаблонов или фильтр по тегам.
3. В нижней панели выбирает нужный шаблон по миниатюре.
4. В центральной области проверяет превью активной мастер-страницы.
5. В правой панели смотрит карточку шаблона: описание, теги, плейсхолдеры, сопоставления.
6. При необходимости открывает карточку шаблона и редактирует настройки.
7. В настройке мастер-страницы подключает IDMS-сниппеты, задает слои, порядок и параметры плейсхолдеров.
8. После сохранения выбранный шаблон записывается в переменную контекста PySM.
9. Каталогизатор передает конфигурацию, но не строит исполняемый план замен.
10. Генератор разворотов применяет IDMS, инспектирует расширенный IDML и строит собственный план создания документа.

Каталогизатор работает с карточками шаблонов и сниппетов. Физические IDML и IDMS-файлы не изменяются при обычном редактировании карточек.

### Сортировка шаблонов

В контекстном меню панели миниатюр доступно подменю **Сортировка**:

- **По названию** — режим по умолчанию;
- **По имени файла** — используется только основа имени IDML без пути и расширения;
- **По типу шаблона** — шаблоны группируются по отображаемому названию типа, а внутри типа сортируются по названию.

Во всех режимах используется естественная сортировка по возрастанию без учета регистра: например, `Шаблон 2` располагается раньше `Шаблон 10`. Фильтры категории и тегов не изменяются. В управляемом запуске выбранный режим сохраняется в переменной состояния окна и восстанавливается при следующем запуске.

## 5. Данные и настройки

### Каталог шаблонов

Каталог шаблонов хранит список шаблонов, категории и настройки карточек. В карточке шаблона сохраняются:

- идентификатор шаблона;
- название;
- категория;
- путь к IDML-файлу;
- активная мастер-страница;
- список мастер-страниц;
- список слоев;
- графические и текстовые плейсхолдеры;
- сопоставление плейсхолдеров с папками фотографий;
- параметры позиционирования;
- список подключенных IDMS-сниппетов;
- режим генерации;
- теги;
- описание.

### Демонстрационное ограничение

Режим распространения задаётся разработчиком в файле `domain/demo_settings.py` перед
шифрованием исходного кода. Это не параметр запуска и не пользовательская
настройка.

- `DEMO_MAX_TEMPLATES = 0` — полноценный режим без искусственных ограничений;
- `DEMO_MAX_TEMPLATES = N`, где `N > 0`, — демонстрационный режим, допускающий
  не более `N` карточек шаблонов.

При достижении лимита создание и копирование карточек блокируются с понятным
сообщением. Существующие карточки не скрываются и не удаляются: их можно
просматривать, редактировать и удалять. Если открытый каталог уже содержит
больше карточек, чем разрешено, добавление станет доступно только после
уменьшения их количества ниже лимита.

Пути к шаблонам и сниппетам по возможности хранятся относительно каталога. Это позволяет переносить каталог на другой компьютер или в другую папку без ручного исправления всех путей.

### Карточка шаблона

Карточка шаблона содержит основные сведения о шаблоне и вкладку настройки мастер-страницы.

В карточке можно:

- выбрать или заменить IDML-файл;
- указать название, категорию, формат, тип, дизайн и описание;
- выбрать активную мастер-страницу;
- назначить теги;
- проверить список графических и текстовых плейсхолдеров;
- настроить таблицу "Плейсхолдеры и позиционирование";
- подключить IDMS-сниппеты к активной мастер-странице.

### Режим `multipage_vignette`

Для многостраничной виньетки выберите тип **Многостраничная виньетка** и
настройте все мастер-страницы, которые должны участвовать в генерации.

В этом режиме Каталогизатор передает Генератору:

- UID и уникальное понятное имя каждой мастер-страницы;
- графические и текстовые метки каждого мастера;
- индивидуальные сопоставления папок;
- индивидуальные графические и текстовые override;
- настройки позиционирования;
- IDMS-привязки всех участвующих мастеров;
- активный мастер как стартовую точку.

Порядок словаря мастеров не используется. Генератор выполняет естественную
сортировку по имени (`page2` раньше `page10`), начинает с активного мастера и
идет до конца списка без циклического возврата.

Одинаковая метка, например `portrait_0`, может присутствовать на нескольких
мастерах. Ее настройки хранятся отдельно внутри каждого мастера.

### Режим `multipage_personal_vignette`

Для многостраничной персональной виньетки выберите тип
**Многостраничная персональная виньетка**.

Каталогизатор передаёт Генератору тот же полный многомастерный контракт, что
и для `multipage_vignette`: все мастера, их точные метки, карты папок,
override, параметры позиционирования и IDMS-привязки.

Настройте каждый участвующий мастер отдельно:

- `portrait_N` формируют очередную порцию общей классной виньетки;
- только `portrait_N` и `teacher_N` являются специализированными рамками
  общей виньетки;
- любая другая рамка, включая `group_photo_01`, `group_photo_all_01` и
  `portrait`, становится персональной при включённом графическом override;
- персональные тексты, например `child_fullname`, должны иметь текстовый
  override;
- одинаковая метка на разных мастерах может иметь разные настройки.

Мастер без персональной рамки создаст один общий разворот. Мастер с
персональной рамкой создаст по одному развороту для каждого ученика полного
списка. Если персональная рамка есть на нескольких мастерах, каждый из них
создаст собственную полную серию.

Override специализированных рамок `portrait_N` и `teacher_N` не меняет их
назначение: они остаются общей частью виньетки и одинаково повторяются на
обычных разворотах. Для всех остальных рамок числовой суффикс не имеет
специального значения: `group_photo_01`, `group_photo_10`,
`group_photo_all_01` и `portrait` являются общими без override и
персональными при включённом override.
Персональные серии не влияют на распределение учеников между `portrait_N`.

В параметрах режима доступен
`move_duplicate_small_portrait`. По умолчанию он выключен. Если его включить,
Генератор может убрать с персонального разворота маленький портрет текущего
ученика, совпадающий с большой персональной фотографией.

### Повторная загрузка IDML

При выборе IDML-файла Каталогизатор заново считывает структуру шаблона: мастер-страницы, слои, графические и текстовые плейсхолдеры.

InDesign может пересоздавать внутренние UID мастер-страниц при повторном экспорте документа в IDML. Поэтому Каталогизатор сохраняет не только технический UID, но и имя активной мастер-страницы. Если после переэкспорта IDML старый UID больше не найден, карточка автоматически восстанавливает активную мастер-страницу, настройки плейсхолдеров и подключенные IDMS-сниппеты по имени мастер-страницы.

Если мастер-страница была переименована и ее нельзя сопоставить по сохраненному имени, Каталогизатор показывает предупреждение и выбирает первую доступную мастер-страницу. Старый UID не используется как эвристика: после переэкспорта он может принадлежать уже другой мастер-странице. В этом случае нужно вручную проверить активную мастер-страницу, подключенные сниппеты и настройки плейсхолдеров.

Базовые имена (`BaseName`) доступных мастер-страниц в IDML должны быть уникальными. Сравнение выполняется без учета регистра и пробелов по краям; префикс мастер-страницы в проверке не участвует. Если несколько мастер-страниц имеют одинаковое базовое имя, Каталогизатор блокирует сохранение карточки и просит переименовать страницы в InDesign. Автоматический выбор между одноименными страницами не выполняется.

Если после изменения IDML не удалось сопоставить неактивную мастер-страницу, Каталогизатор отдельно предупреждает о ней и о привязанных к ней сниппетах. Такие привязки удаляются из карточки только после явного сохранения диалога; отмена сохраняет прежнюю карточку без изменений.

Перед записью выбранного шаблона в контекст PySM мастер-страница повторно сверяется с текущим IDML, даже если пользователь не менял выбранную карточку. Поэтому устаревший UID не передается Генератору без предварительной проверки. Если сохраненный мастер был переименован, в контекст выбирается первая доступная мастер-страница и показывается предупреждение.

Поврежденный, неполный или некорректный IDML не приводит к падению диалога. Карточка открывается только для просмотра сохраненных данных, а ее сохранение блокируется до исправления исходного файла.

Если плейсхолдер с таким же именем уже был в карточке, его пользовательские настройки сохраняются:

- папка или значение;
- признак переопределения;
- `eye_line`;
- `face_scale`.

Настройки плейсхолдеров, которых больше нет ни в обновленном IDML, ни в подключенных сниппетах, удаляются вместе с метками. В сохраненных данных не остаются устаревшие записи позиционирования.

Если появился новый специализированный графический плейсхолдер, например
`portrait_32`, Каталогизатор пытается унаследовать настройки от существующих
`portrait_N`. Такое наследование графических настроек действует только для
семейств `portrait_N` и `teacher_N`.

Нумерованные графические и текстовые плейсхолдеры одинаково сохраняются с
точными числовыми суффиксами. Объединенная строка `child_name_*` в таблице
является только представлением интерфейса: при включении `Override` в карточке
сохраняются и передаются Генератору все фактические метки `child_name_0`,
`child_name_1` и далее. Старые карточки, в которых было сохранено только
базовое имя `child_name`, автоматически преобразуются по меткам, реально
найденным в текущем IDML. Правила объединения графических меток описаны в
разделе «Нумерованные плейсхолдеры».

## 6. IDMS-сниппеты

### Назначение сниппетов

IDMS-сниппет - это фрагмент InDesign-документа, который можно подключить к мастер-странице шаблона. В текущем сценарии сниппеты используются для расширения исходного шаблона: дополнительные рамки, декоративные элементы, текстовые блоки, фоновые элементы и варианты оформления.

Сниппеты вставляются только в мастер-страницы. После вставки Генератор работает с расширенной мастер-страницей как с обычной частью IDML-шаблона.

### Каталог IDMS-сниппетов

Каталог IDMS-сниппетов содержит отдельные карточки сниппетов. В карточке сохраняются:

- идентификатор сниппета;
- название;
- категория;
- путь к IDMS-файлу;
- размер исходной страницы сниппета в миллиметрах;
- размер превью в пикселях;
- графические плейсхолдеры;
- текстовые плейсхолдеры;
- предупреждения;
- теги;
- описание.

Превью сниппета должно лежать рядом с IDMS-файлом и иметь такое же имя, но расширение `.jpg`, `.jpeg` или `.png`.

В контекстном меню дерева категорий каталога сниппетов доступны операции массового обмена:

- "Обновить категорию" — повторно считывает актуальные IDMS всех сниппетов
  выбранной категории и её подкатегорий. Обновляются графические и текстовые
  метки, размеры страницы, размеры превью и предупреждения. Пользовательские
  теги, название, описание, категория и идентификатор карточки сохраняются.
  Обработка выполняется в фоне; при отмене каталог остается без изменений.
  Недоступные или поврежденные IDMS перечисляются в отчете, а их карточки не
  стираются.
  После завершения нужно нажать «Сохранить» в окне каталога; закрытие через
  «Отмена» отбрасывает обновление.
- "Импортировать сниппеты из папки" - добавляет все `.idms` из выбранной папки в текущую категорию без рекурсивного обхода подпапок. Если такой IDMS уже есть в каталоге, карточка обновляется, а дубль не создается. Обработка выполняется в фоне с индикатором прогресса; при отмене рабочая копия каталога остается без изменений, а индикатор безопасно закрывается после остановки импорта.
- "Экспортировать категорию в JSON" - сохраняет карточки выбранной категории и ее подкатегорий в отдельный JSON-файл. Для пункта "Без категории" экспортируются только сниппеты без категории.
- "Импортировать сниппеты из JSON" - добавляет или обновляет карточки из JSON в текущей категории. Импорт в пункт "Все сниппеты" не выполняется, потому что это фильтр, а не реальная категория.

Массовый импорт и импорт из JSON изменяют рабочую копию каталога в диалоге. Чтобы записать изменения в `snippets_catalog.json`, нужно нажать "Сохранить".

В отчете импорта существующий IDMS, найденный в другой категории, считается перенесенным, а не обновленным. Это означает, что карточка не продублирована, а перемещена в выбранную категорию.

### Размер исходной страницы

Размер исходной страницы сниппета нужен для точного размещения сниппета на целевой мастер-странице. Размер указывается в миллиметрах.

Если размер страницы сниппета совпадает с размером целевой мастер-страницы, сниппет вставляется без масштабирования.

Если размеры отличаются, можно вставить сниппет без масштабирования, пропорционально масштабировать его по ширине или высоте мастер-страницы либо отменить подключение. Масштабирование используется для практических случаев, когда размеры обложек отличаются на несколько миллиметров из-за толщины альбома.

### Подключение сниппета к мастер-странице

В таблице "IDMS-сниппеты активной мастер-страницы" для каждого подключенного сниппета задаются:

- видимость сниппета на составном превью;
- порядок применения;
- название сниппета;
- целевой слой;
- список плейсхолдеров.

В таблице "Плейсхолдеры и позиционирование" колонка "Сниппет" позволяет быстро включить или отключить показ подключенного сниппета, которому однозначно принадлежит текущий плейсхолдер. Это помогает визуально проверить расположение рамки или текстового поля на составном превью.

Если плейсхолдер относится к базовому шаблону, в колонке отображается прочерк. Если строка объединяет метки из разных источников или одинаковая метка используется несколькими сниппетами, вместо чекбокса показывается текстовое состояние с пояснением во всплывающей подсказке.

При выборе строки в таблице подключенных сниппетов составное превью визуально выделяет выбранный сниппет: поверх обычного превью накладывается полупрозрачная цветная плашка, затем выбранный PNG-слой. Для визуальной проверки временно показывается и выбранный отключенный сниппет, но в обычное составное превью он не входит. Перемещение по строкам обновляет выделение с короткой задержкой, не меняет текущий масштаб просмотра и не записывает служебную подсветку в итоговый JPG. Если выделенных строк нет, показывается обычное составное превью без цветной подложки.

При переходе между секциями сниппетов и плейсхолдеров выделения строк и временные подсветки сбрасываются. После выбора строки плейсхолдера слева выделяется миниатюра назначенной папки, а на составном превью — однозначно определенный сниппет-владелец. Подложка сниппета и миниатюра используют единый цвет выделения. Для базового плейсхолдера либо строки с несколькими владельцами подсветка сниппета не используется.

Доступные действия:

- добавить сниппет;
- удалить сниппет;
- заменить сниппет;
- переместить выше или ниже;
- сохранить пресет;
- загрузить пресет.

Сниппет можно разместить на конкретный слой шаблона или оставить режим "исходные слои". В режиме "исходные слои" элементы сниппета размещаются на слоях с теми же именами, что были в исходном IDMS.

### Конфликты плейсхолдеров

Сниппет может содержать плейсхолдеры с такими же именами, как в шаблоне или в других сниппетах. Это разрешено.

Каталогизатор не блокирует такое подключение, но показывает информацию о совпадениях. Для Генератора все плейсхолдеры с одинаковой меткой считаются одним логическим плейсхолдером.

При удалении сниппета Каталогизатор удаляет только те плейсхолдеры, которые больше не встречаются ни в IDML-шаблоне, ни в других подключенных сниппетах. Это защищает от "пропавших" плейсхолдеров при совпадающих метках.

## 7. Плейсхолдеры и позиционирование

### Графические плейсхолдеры

Графические плейсхолдеры - это рамки InDesign, в которые Генератор вставляет фотографии. Поддерживаются прямоугольные рамки, овальные рамки и многоугольники, если они используются как графические контейнеры.

Для каждого графического плейсхолдера задается:

- метка;
- область применения;
- папка фотографий;
- признак переопределения;
- `eye_line`;
- `face_scale`.

Поле "Папка / значение" обычно содержит имя подпапки с фотографиями, например:

```text
portrait
group_photo_table
```

Значение выбирается только из списка доступных папок. Ручной ввод произвольного имени запрещен. Если сохраненное ранее имя отсутствует в актуальном списке, поле отображается без выбранного значения до назначения доступной папки.

При выборе строки графического плейсхолдера соответствующая миниатюра папки в левой панели выделяется и автоматически прокручивается в видимую область. Если выбран текстовый плейсхолдер либо для назначенной папки нет превью, выделение миниатюры снимается.

### Текстовые плейсхолдеры

Текстовые плейсхолдеры записываются в тексте InDesign как значения в двойных фигурных скобках:

```text
{{child_fullname}}
{{полное название школы}}
```

В карточке шаблона они отображаются без ручного поиска по IDML.

### Переопределение

Переопределение определяет, где будет заменяться плейсхолдер:

- если переопределение выключено, значение заменяется на мастер-странице один раз;
- если переопределение включено, объект переопределяется на обычных разворотах и может получать разные значения на каждом развороте.

Для персональных разворотов обычно переопределяются портрет и имя ученика. Для общих текстов, например названия школы или класса, переопределение обычно не требуется.

### `eye_line` и `face_scale`

`eye_line` задает положение линии глаз внутри рамки. Значение указывается как доля высоты рамки.

`face_scale` задает относительный масштаб лица при вписывании фотографии в рамку.

Эти параметры используются Генератором для более устойчивого позиционирования портретов.

### Нумерованные плейсхолдеры

Каталогизатор сортирует нумерованные плейсхолдеры естественным образом:

```text
portrait_1
portrait_2
portrait_10
```

а не как обычные строки:

```text
portrait_1
portrait_10
portrait_2
```

Новые нумерованные плейсхолдеры автоматически получают настройки от существующих плейсхолдеров с тем же префиксом, если такие настройки уже есть.

Нумерованные текстовые семейства и специализированные графические семейства
`portrait_N`, `teacher_N` из двух и более меток отображаются одной строкой с
маской, например `child_fullname_*` или `portrait_*`. Изменение настройки в
этой строке применяется ко всем точным меткам семейства.

Другие графические метки с числовым суффиксом не объединяются. Например,
`group_photo_01`, `group_photo_02` и `group_photo_all_01` отображаются
отдельными строками, чтобы каждой рамке можно было независимо назначить папку,
override, `eye_line` и `face_scale`.

Если точные плейсхолдеры одной группы имеют разные значения override, чекбокс группы показывает промежуточное состояние. Следующий клик явно включает или выключает override сразу для всей группы.

Если в одном мастере одновременно существуют `child_fullname` и
`child_fullname_N`, это независимые метки. Override ненумерованного
`child_fullname` не включает семейство `child_fullname_N`. Разворачивание
старого базового имени в нумерованное семейство применяется только тогда,
когда точной ненумерованной метки в текущем шаблоне нет.

## 8. Дополнительные настройки

### Теги

Теги используются для быстрого поиска шаблонов и сниппетов. У каждого тега есть:

- название;
- цвет;
- описание.

Теги отображаются в интерфейсе цветными метками. Цвет используется в карточках, справочнике тегов и фильтрах.

Цветные теги в HTML-карточках шаблонов и сниппетов кликабельны: клик открывает вкладку "Теги" и включает или отключает соответствующий чекбокс фильтра.

Справочник тегов общий для шаблонов и сниппетов.

### Состояние окон

Каталогизатор сохраняет состояние главного окна и основных диалогов: размер, положение, пропорции сплиттеров и ширину колонок таблиц, где это применимо.

Состояние сохраняется в контексте PySM и восстанавливается при следующем открытии соответствующего окна. В автономном запуске без контекста PySM диалоги работают с размерами по умолчанию.

### Фильтр по тегам

Фильтр работает по логике "И": если выбрано несколько тегов, объект должен иметь все выбранные теги.

Состояние фильтров сохраняется:

- для шаблонов - в переменную контекста `wf_indesign_template.tag_template`;
- для сниппетов - в переменную контекста `wf_indesign_template.tag_snippet`.

При следующем запуске Каталогизатора фильтр восстанавливается.

### Пресеты сниппетов

Пресет сниппетов сохраняет список подключенных сниппетов активной мастер-страницы:

- идентификатор сниппета;
- порядок;
- видимость;
- целевой слой;
- режим размещения.

При загрузке пресета таблица сниппетов пересобирается, а таблица плейсхолдеров обновляется на основе актуального состава IDML и сниппетов.

### Пресеты плейсхолдеров

Пресет плейсхолдеров сохраняет только параметры позиционирования и переопределения:

- `override`;
- `eye_line`;
- `face_scale`.

Поле "Папка / значение" в этот пресет не входит. Это сделано намеренно: сопоставление папок зависит от конкретного шаблона и набора фотографий.

## 9. Превью, файлы и артефакты

### Превью шаблона

Для отображения шаблона в каталоге используется изображение-превью. Обычно оно лежит рядом с IDML-файлом или в папке превью и имеет имя, связанное с шаблоном.

Для активной мастер-страницы может формироваться составное превью: исходное превью мастер-страницы плюс видимые IDMS-сниппеты.

Составное превью учитывает выбранный режим размещения каждого сниппета: без масштабирования, по ширине или по высоте мастер-страницы.

Составное превью сохраняется под именем
`<имя IDML>_<название шаблона>_<имя мастер-страницы>_<ID карточки>_catalog_preview.jpg`
в служебной папке `_CatalogPreviews`, расположенной рядом с папкой `templates`.
Внутри `_CatalogPreviews` повторяется относительная структура подпапок `templates`.
В имя включается устойчивый идентификатор карточки, поэтому независимые составные
превью гарантированы даже для карточек с одинаковыми названиями и общим IDML.
Очень длинные части имени безопасно сокращаются без потери уникальности файла.

Базовые JPG- и PNG-превью по-прежнему загружаются из папки исходного IDML.
Скрипт также распознаёт составные превью, ранее сохранённые рядом с IDML.
Если сформированное превью отсутствует, это не считается ошибкой: используется
доступное базовое превью, а составной файл заново создаётся при следующем
сохранении карточки шаблона.

Если исходный IDML находится вне папки `templates` текущего каталога, его
составное превью всё равно сохраняется внутри `_CatalogPreviews/_external` этого
каталога. Скрипт не создаёт служебное хранилище рядом с внешним IDML.

### Превью сниппета

Превью IDMS-сниппета используется:

- в каталоге сниппетов;
- в диалоге выбора сниппета;
- при формировании составного превью мастер-страницы.

Если сниппет имеет прозрачный фон, в миниатюрах и окне выбора добавляется подложка или рамка, чтобы было видно реальное положение объектов на странице.

### Кэширование изображений

Миниатюры и крупные превью загружаются через общий API кэша изображений PySM.
Декодирование выполняется в фоновом пуле, поэтому открытие каталога и
переключение категорий не должны блокировать отрисовку интерфейса. Повторные
обращения используют ограниченный по памяти LRU-кэш, а уменьшенные миниатюры —
атомарно записываемый дисковый кэш в `.thumbnails/shared-v1` рядом с каталогом.

Ключ кэша учитывает путь, размер и время изменения исходного файла, параметры
масштабирования и версию алгоритма. После изменения исходного превью устаревшая
миниатюра автоматически перестает использоваться. Пользователю не требуется
очищать кэш вручную.

### Выбор сниппета

При добавлении сниппета к мастер-странице в окно выбора передается текущее составное превью мастер-страницы. Выбранный сниппет накладывается поверх этого превью, чтобы пользователь видел, как он ляжет на страницу до подключения.

### Папка `SnippetPreviews`

Каталогизатор не создает папку `SnippetPreviews`. Эта папка относится к диагностическому режиму Генератора разворотов и по умолчанию отключена.

## 10. Проверка и диагностика

Каталогизатор выполняет проверки при чтении IDML и IDMS:

- доступность файлов;
- наличие превью;
- список мастер-страниц;
- список слоев;
- графические и текстовые плейсхолдеры;
- предупреждения IDMS, например объекты без меток;
- совпадения плейсхолдеров;
- размер исходной страницы сниппета.

Если обнаружена проблема, нужно проверить карточку шаблона или карточку сниппета. Наиболее частые причины:

- IDML или IDMS перемещен, а путь в карточке устарел;
- отсутствует превью;
- в сниппете есть объекты без меток;
- размер страницы сниппета не соответствует целевой мастер-странице;
- сниппет содержит внешние связанные файлы, которые доступны только на исходном компьютере.

## 11. Практические правила

- Создавайте сниппеты на странице того же размера, что и целевая мастер-страница.
- Для переносимых каталогов храните IDML, IDMS, превью и папку `_Designs_` рядом с каталогом.
- Используйте понятные метки плейсхолдеров: `portrait_0`, `portrait_1`, `group_photo_01`.
- Не включайте переопределение для общих текстов, которые должны заменяться один раз на мастер-странице.
- Для вариантов оформления используйте IDMS-сниппеты, а не отдельные копии почти одинаковых IDML-шаблонов.
- Проверяйте составное превью перед сохранением шаблона.
- Если несколько сниппетов используют одинаковые метки, убедитесь, что это сделано намеренно.
- Для слотов виньетки используйте специализированные метки `portrait_N` и
  `teacher_N`; остальные графические рамки настраиваются независимо.
