# Скрипт "Выборка и переименование файлов" (v2025.10.19)

## 1. Назначение

Этот скрипт является мощным инструментом для автоматизации отбора и организации фотографий. Он решает задачу, когда клиент присылает список номеров желаемых фотографий. Скрипт находит все нужные файлы, автоматически переименовывает их, используя имя человека с фотографии, и ведет подробный журнал всех выполненных операций.

## 2. Логика работы

1.  **Запуск:** Скрипт автоматически определяет рабочие папки и пути к файлам данных (`info_portrait_faces.json`, `operations_log.json`) на основе информации о текущем рабочем процессе (workflow) из PySM.

2.  **Ввод текста:** Пользователь вставляет в левую панель любой текст, содержащий 4-значные номера фотографий.

3.  **Поиск файлов и имен:** После нажатия кнопки "2. Найти файлы":
    *   Скрипт извлекает из текста все уникальные 4-значные числа.
    *   Загружает данные из `info_portrait_faces.json` для сопоставления номеров с именами людей.
    *   Сканирует исходную папку и находит все файлы, соответствующие извлеченным номерам.
    *   Результаты выводятся в **интерактивную таблицу** с возможностью **сортировки** по любой колонке. Под таблицей появляется **поле для копирования** всех найденных номеров.

4.  **Выполнение операции:**
    *   **Выбор сессии:** Перед выполнением пользователь должен выбрать имя для текущей сессии копирования из выпадающего списка (список загружается из переменной контекста `sys_location_name`).
    *   **Копирование/Перемещение:** Скрипт копирует или перемещает каждый найденный файл в **целевую подпапку сессии** (например, `.../Selects/SCHOOL/Фото на альбом/`), сохраняя структуру подпапок и применяя новое имя.
    *   **Конфликты:** По умолчанию, если в целевой папке уже существует файл с таким же именем, он будет **пропущен**. Это поведение можно изменить на перезапись (`overwrite`) с помощью параметра `__fs_on_conflict`.
    *   **Логирование:** После успешного завершения информация о скопированных/перемещенных RAW-файлах добавляется в файл `operations_log.json`.

## 3. Требования

-   Для корректной работы скрипт должен запускаться в среде PySM с правильно настроенными переменными контекста (`wf_...`, `sys_location_name`).
-   В соответствующих папках должен находиться файл `info_portrait_faces.json`.

## 4. Параметры

-   **`__fs_mode`** (служебный): Определяет, будет ли скрипт копировать (`copy`) или перемещать (`move`) файлы. По умолчанию `copy`.
-   **`__fs_on_conflict`** (служебный): Определяет поведение при конфликте имен в целевой папке.
    -   `skip` (по умолчанию): Пропускать файлы, которые уже существуют.
    -   `overwrite`: Перезаписывать существующие файлы.

## 5. История изменений

### Версия 2025.10.19
-   **Добавлено:** Сортировка в таблице результатов. Теперь можно сортировать найденные файлы по любой колонке, кликая по ее заголовку.
-   **Добавлено:** Поле для копирования номеров. Под таблицей результатов теперь отображается текстовая строка со всеми найденными номерами для удобного копирования.
-   **Улучшено:** Полная интеграция с темами оформления PySM. Цвета для подсветки номеров в тексте (`ipymarkup`) и для статусов в таблице (`Найден`/`Не найден`) теперь полностью настраиваются через `theme.toml`.
-   **Исправлено:** Устранена проблема, из-за которой цвет текста при подсветке номеров не применялся.

### Версия 2025.10.18
-   **Добавлено:** Гибкое формирование целевой папки. Теперь для каждой сессии копирования автоматически создается одноименная подпапка внутри `Selects`.
-   **Добавлено:** Система ведения журнала операций в `operations_log.json`.
-   **Добавлено:** Выбор сессии копирования из выпадающего списка (загружается из переменной контекста `sys_location_name`).
-   **Добавлено:** Настраиваемая обработка конфликтов (`__fs_on_conflict`).
-   **Исправлено:** Восстановлена корректная работа прогресс-бара по файлам.

### Версия 2025.10.17
-   **Добавлено:** Функция переименования файлов по шаблону `<Имя Человека>-<Номер>`.
-   **Улучшено:** Реализована высокоэффективная загрузка данных из `info_portrait_faces.json` с помощью `ijson`.
-   **Улучшено:** Централизовано формирование всех путей на основе переменных контекста.
