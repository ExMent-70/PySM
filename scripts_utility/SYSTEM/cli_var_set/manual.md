# Скрипт "Установка значения (CLI)" (v2.2026.07.07)

## 1. Назначение

Скрипт **"Установка значения (CLI)"** предназначен для сохранения текстового значения в переменную контекста без взаимодействия с пользователем (в "тихом" режиме).

Это особенно полезно для:
*   Инициализации значений по умолчанию в начале цепочки.
*   Передачи конфигурационных параметров.
*   Автоматической обработки данных, где значения известны заранее, но требуют проверки формата (валидации).

## 2. Параметры

Скрипт принимает следующие аргументы командной строки:

-   **Имя переменной** (`set_var_name`) **[Обязательно]**:
    -   Имя ключа в контексте, под которым будет сохранено значение.
    -   Поддерживается точечная нотация для вложенных JSON-значений, например `project.name`.
-   **Значение** (`set_var_value`):
    -   Текст, который нужно сохранить. Если оставить пустым, будет сохранена пустая строка.

### Система валидации

Даже без графического интерфейса скрипт обеспечивает защиту данных. Перед сохранением значение проверяется на соответствие выбранному типу.

-   **Тип валидации** (`set_valid_type`):
    -   **Описание:** Определяет правило проверки.
    -   **Варианты:**
        -   `none`: **(По умолчанию)** Проверка отключена. Сохраняется любое значение.
        -   `not_empty`: Значение не должно быть пустым.
        -   `filename_txt`: Имя файла с расширением .txt.
        -   `integer`: Целое число.
        -   `positive_integer`: Положительное целое число или ноль.
        -   `float`: Число с плавающей точкой.
        -   `email`: Адрес электронной почты.
        -   `custom`: **Пользовательский режим**. Требует настройки следующих полей.

-   **Пользовательский шаблон** (`set_custom_regexp`):
    -   Регулярное выражение для проверки (активно только при типе `custom`).

-   **Описание пользовательского шаблона** (`set_custom_regexp_desc`):
    -   Текст ошибки, который попадет в лог, если проверка не пройдет (активно только при типе `custom`).

## 3. Логика работы

### 3.1. Валидация
Скрипт проверяет переданное в параметре `set_var_value` значение. Проверка выполняется **до** попытки сохранения в контекст.

### 3.2. Управление потоком выполнения (коды выхода)

Скрипт работает синхронно и возвращает код выхода, который влияет на дальнейшее выполнение цепочки скриптов в PySM:

-   **Код выхода `0` (Успех):**
    -   **Условие:** Значение прошло валидацию (или валидация отключена).
    -   **Действие:** Значение успешно записано в контекст. Следующий скрипт в цепочке будет запущен.

-   **Код выхода `1` (Ошибка):**
    -   **Условие:** Значение **не соответствует** выбранному типу валидации.
    -   **Действие:**
        1.  В лог записывается сообщение об ошибке (или описание из `set_custom_regexp_desc`).
        2.  **Никакие данные в контекст не сохраняются.**
        3.  Выполнение всей цепочки скриптов будет **остановлено** (если в менеджере включена остановка по ошибкам).

## 4. Примеры использования

**Пример 1: Простая инициализация**
**Задача:** Задать папку для экспорта по умолчанию в начале работы.
-   `Имя переменной`: `export_path`
-   `Значение`: `C:\Results`
-   `Тип валидации`: `not_empty`

**Пример 2: Строгая типизация конфигурации**
**Задача:** Установить количество попыток соединения (должно быть числом), которое передается из другого источника.
-   `Имя переменной`: `retry_count`
-   `Значение`: `5`
-   `Тип валидации`: `positive_integer`

**Пример 3: Запись во вложенное значение**
**Задача:** Сохранить название проекта внутри JSON-переменной `project`.
-   `Имя переменной`: `project.name`
-   `Значение`: `Школьный альбом`

*Примечание: Если в `Значение` случайно попадет текст "пять" или "-1", скрипт завершится с ошибкой и остановит выполнение, предотвратив сбои в дальнейших скриптах.*
