# План разработки `py_path_if_else`

## 1. Назначение

Создать отдельный read-only скрипт условной маршрутизации для проверок файлов и
папок. Скрипт не изменяет файловую систему, а только вычисляет условие и выбирает
ветку `Then` или `Else` через контекст PySM.

Существующий `py_if_else` остаётся скриптом проверки значений контекста и не
изменяется.

## 2. Состав скрипта

```text
scripts_utility/SYSTEM/py_path_if_else/
├── run_py_path_if_else.py
├── script_passport.json
├── manual.md
├── CHANGELOG.md
├── DEVELOPMENT_PLAN.md
└── _tests/
    └── test_py_path_if_else.py
```

## 3. CLI-контракт

- `--checked-path` — проверяемый путь с поддержкой шаблонов `{variable}`;
- `--condition` — файловое условие;
- `--patterns` — glob-шаблоны для поиска файлов, по умолчанию `*`;
- `--recursive` — поиск во вложенных папках;
- `--then-instance-id` — переход при результате `TRUE`;
- `--else-instance-id` — необязательный переход при результате `FALSE`.

Имя `checked_path` позволяет `ConfigResolver` автоматически подставлять переменные
контекста и разрешать относительные пути. Имена `condition` и `patterns` намеренно
не содержат слов `path` и `file`, чтобы resolver не пытался преобразовать их в
пути.

## 4. Условия первой версии

1. `путь существует`;
2. `путь не существует`;
3. `файл существует`;
4. `файл не существует`;
5. `папка существует`;
6. `папка не существует`;
7. `папка пуста`;
8. `папка не пуста`;
9. `папка содержит файлы`;
10. `папка не содержит файлы`.

Пустота папки означает отсутствие любых непосредственных элементов. Условия
поиска учитывают только файлы, поддерживают несколько glob-шаблонов и
опциональный рекурсивный обход.

## 5. Безопасность и ошибки

- Скрипт выполняет только операции чтения.
- Абсолютные glob-шаблоны, шаблоны с диском и сегменты `..` запрещены.
- Ошибки обязательных параметров завершают запуск с кодом `1`.
- Отсутствующий или неверный тип объекта даёт контролируемый `FALSE` и
  предупреждение, когда условие требует существующую папку.
- Ошибки доступа не выводят traceback и направляют выполнение в `Else`.

## 6. Логирование

Отчёт содержит путь, условие, состояние объекта, шаблоны, режим рекурсии,
количество и несколько примеров совпадений, итог `TRUE/FALSE`, выбранную ветку и
целевой `instance_id`. Все пользовательские значения экранируются для HTML.

## 7. Документация и версия

- Описать контракт и примеры в `manual.md`.
- Добавить параметры в `script_passport.json`.
- Использовать версию `2.2026.07.10`.
- Зафиксировать первую реализацию в локальном `CHANGELOG.md`.

## 8. Проверки

Тесты во временных каталогах должны покрывать существование пути, тип объекта,
пустые и непустые папки, glob-шаблоны, рекурсию, дедупликацию, небезопасные
шаблоны и маршрутизацию.

Финальные команды:

```powershell
D:\PySM3_Codex\envs\pysm\python.exe -m unittest discover scripts_utility/SYSTEM/py_path_if_else/_tests
D:\PySM3_Codex\envs\pysm\python.exe -m compileall scripts_utility/SYSTEM/py_path_if_else
D:\PySM3_Codex\envs\pysm\python.exe scripts_utility/SYSTEM/py_path_if_else/run_py_path_if_else.py --help
git diff --check
```

## 9. Отложенные возможности

В первую версию не входят сравнение количества файлов, проверка размера и дат,
регулярные выражения, контрольные суммы, ожидание появления файла и проверка прав
на запись.
