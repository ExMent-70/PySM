# Скрипт "Условный переход" (v2.2026.04.17)

## 1. Назначение

Скрипт **"Условный переход"** — это мощный инструмент для создания нелинейных рабочих процессов. Он позволяет прервать стандартную последовательность выполнения скриптов и "перепрыгнуть" к любому другому скрипту в рамках текущего набора.

Это дает возможность реализовывать сложную логику, такую как:
-   **Циклы:** вернуться к предыдущему скрипту для повторной обработки.
-   **Ветвление:** в зависимости от какого-либо условия, перейти к разным веткам обработки.

Скрипт поддерживает два режима работы:
1.  **Интерактивный (по умолчанию):** Отображает пользователю диалоговое окно для выбора следующего шага.
2.  **Программный (через параметр):** Осуществляет переход к скрипту с заранее известным ID без участия пользователя.

**Внимание:** Этот скрипт работает только в среде PySM.

## 2. Параметры
`dlg_goto_script_id` - ID экземпляра скрипта (или нескольких скриптов), к которому нужно перейти.

Если параметр `dlg_goto_script_id` задан
1.  Скрипт не отображает никаких сообщений.
2.  Скрипт завершается с кодом **`0` (Успех)**.

## 3. Логика работы

Система маршрутизации PySM автоматически адаптирует поведение скрипта перехода в зависимости от того, **сколько** скриптов выбрано в качестве цели и **где** они находятся.
Существует два фундаментальных типа переходов: **Локальный переход (GOTO)** и **Вызов подпрограммы (GOSUB)**.

#### Тип 1. Локальный переход (GOTO) — "Перемотка ленты"
**Когда срабатывает:** Если целевой скрипт находится **В ТОМ ЖЕ НАБОРЕ**, что и вызывающий скрипт.

**Как это работает:**
PySM воспринимает это как команду "Перемотать выполнение на указанную точку".
*   Он смещает внутренний указатель на выбранный скрипт.
*   Выполняет его.
*   Затем **продолжает выполнение всех скриптов, идущих ниже него** до самого конца текущего набора.
*   *Возврата назад не происходит.*

**Пример использования:**
У вас есть набор: `[1. Загрузка] -> [2. Переход к скрипту 4] -> [3. Очистка] -> [4. Финал]`.
Скрипт 2 выполняет локальный переход на скрипт 4. Скрипт 3 просто игнорируется. Выполнение завершается после скрипта 4.

#### Тип 2. Вызов подпрограммы (GOSUB / Динамический Макрос)
**Когда срабатывает:** Если вы выбрали **ОДИН** или **НЕСКОЛЬКО** скриптов (галочками в диалоге выбора) находящиеся **В ДРУГОМ НАБОРЕ**.


**Как это работает:**
PySM воспринимает это как команду "Сделай это дополнительное задание и возвращайся".
*   Он ставит текущий набор на **паузу**.
*   Собирает выбранные вами скрипты в "Виртуальный макрос".
*   Выполняет **ТОЛЬКО** выбранные скрипты в указанном порядке. Соседние скрипты в целевом наборе проигнорируются!
*   Когда макрос выполнен, программа **возвращается** в исходный набор и продолжает выполнение скрипта, следующего за тем, который инициировал переход.

**Пример использования (Вызов утилит):**
У вас есть *Набор №1 (Обработка)*: `[А. Коррекция] -> [B. ПЕРЕХОД] -> [C. Сохранение]`.
И есть отдельно лежащий *Набор №2 (Утилиты)*: `[X. Водяной знак]`, `[Y. Ресайз]`, `[Z. Отправка на FTP]`.
В скрипте `B` в настройках переходы выбраны скрипты `[X]` и `[Z]`.
**Поток выполнения будет таким:** Скрипт `A` -> Скрипт `B` -> (уходим в макрос) -> Скрипт `X` -> Скрипт `Z` -> (возвращаемся) -> Скрипт `C`.

#### Важные правила и ограничения
1. **Запрет рекурсии:** В диалоге выбора скрипт не может выбрать самого себя. Это сделано для защиты от очевидных бесконечных циклов.
2. **Лимит глубины:** Вы можете вызывать макросы внутри макросов (Набор 1 вызывает Набор 2, Набор 2 вызывает Набор 3...). Однако максимальная глубина таких "погружений" ограничена (по умолчанию 20). Если скрипты зациклятся между собой, приложение остановит конвейер и выдаст ошибку во избежание зависания компьютера.
3. **Обмен данными:** Скрипты, вызванные через макросы, имеют полный доступ к тем же переменным контекста, что и вызывающий скрипт. Используйте контекст для передачи параметров в подпрограммы.
