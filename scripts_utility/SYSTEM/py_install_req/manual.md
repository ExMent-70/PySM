# Руководство по скрипту "Установщик зависимостей" (v2.2026.07.16)

## 1. Назначение

Скрипт **"Установщик зависимостей"** автоматически устанавливает Python-пакеты из `requirements.txt` или `pyproject.toml` для выбранного Python-окружения.

Особенность скрипта - построение плана установки с учетом:

* установленной видеокарты;
* CUDA, поддерживаемой NVIDIA-драйвером;
* portable CUDA PySM из `D:\PySM3_Codex\ps_env\CUDA`;
* совместимость wheel с целевым Python;
* уже установленных пакетов.

## 2. Логика работы

1. **Анализ системы.** Скрипт определяет GPU, поддержку CUDA драйвером и portable CUDA PySM.
2. **Выбор CUDA для wheel.** Если portable CUDA найдена и не новее, чем поддерживает драйвер, она используется как предпочтительная версия для CUDA-wheel. В текущей сборке PySM portable CUDA находится в `D:\PySM3_Codex\ps_env\CUDA` и имеет версию `12.8`.
3. **Проверка PyTorch.** Скрипт показывает фактическую версию `torch`, CUDA build и результат `torch.cuda.is_available()` в целевом Python.
4. **Поиск файла зависимостей.** Скрипт ищет `pyproject.toml`, `requirements.txt` и несколько стандартных вариантов `requirements_*.txt`.
5. **Парсинг requirements.** Поддерживаются PEP 508 requirements, environment markers, `-r`, `-c`, pip-options, direct URL, VCS-ссылки, локальные пути, editable-установки и перенос строк через `\`.
6. **Построение плана.** Зависимости делятся на обычные пакеты и специальные категории: `torch`, `onnxruntime`, `triton`, `insightface`.
   Если система выбрала CUDA, специальные GPU-семейства устанавливаются в варианте для выбранной CUDA.
7. **Проверка установленных пакетов.** Перед установкой скрипт сравнивает требования с текущим окружением.
8. **Установка.** Для каждой категории строится отдельная команда `pip` или `uv pip install`.
9. **Отображение прогресса.** Во время реальной установки PySM показывает progress-bar с текущей фазой установки. Если `uv`/`pip` долго скачивает или устанавливает тяжелый wheel, progress-bar продолжает обновляться heartbeat-сообщениями.
10. **Строгий результат.** Если хотя бы одна категория не установилась, скрипт завершится ошибкой и покажет список проблемных категорий. Сообщение об успешной установке выводится только после успешного выполнения всех команд.

После прохода по категориям выводится короткий итог:

```text
ИТОГ ПЛАНА УСТАНОВКИ
[SKIP] Обычные пакеты: уже соответствует
[PLAN] Torch: запланировано
[SKIP] ONNX: уже соответствует
[SKIP] Triton: нет требований
[SKIP] Insightface: уже соответствует
```

При реальной установке вместо `PLAN` используется `OK` или `FAIL`.

В плане установки строки остаются короткими: для точного pin показывается переход версии, для незакрепленных требований - только текущая версия, если она известна. В интерфейсе PySM перед статусом выводятся SVG-иконки из `pysm_icons.py`; в текстовом fallback ниже показаны обычные маркеры.

```text
[U] Обновить: packaging==24.0 (23.2 -> 24.0)
[U] Обновить: Pillow>=10.1 (10.0.0)
[+] Установить: tqdm
[OK] Соответствует: beautifulsoup4 (4.15.0)
```

## 3. Portable CUDA PySM

PySM использует portable CUDA из папки:

```text
D:\PySM3_Codex\ps_env\CUDA
```

Версия читается из:

```text
D:\PySM3_Codex\ps_env\CUDA\version.json
```

Скрипт не пытается собирать или обновлять portable CUDA самостоятельно. Обновление CUDA Toolkit - отдельная операция: нужно получить совместимый набор файлов CUDA Toolkit/cuDNN/TensorRT, проверить драйвер NVIDIA и затем обновить `ps_env\CUDA`. Для установщика зависимостей безопаснее только читать уже подготовленную portable CUDA и выбирать совместимые wheel.

## 4. Wheel-решения и версия Python

`insightface==1.0.1` публикуется как универсальный Python wheel, поэтому старый внешний `cp311` wheel версии 0.7.3 больше не используется. InsightFace устанавливается с `--no-deps`: это не позволяет его зависимости `onnxruntime` автоматически установить CPU-вариант поверх управляемого пакета `onnxruntime-gpu`. Все базовые зависимости InsightFace перечислены в корневом `requirements.txt` и устанавливаются отдельными категориями.

Для `torch` скрипт проверяет не только имя пакета и версию из `pip list`, но и фактическую сборку:

```text
torch.__version__
torch.version.cuda
torch.cuda.is_available()
```

Если выбрана CUDA wheel, но в окружении стоит CPU-сборка `torch`, скрипт принудительно переустановит Torch-пакеты. Для `uv` используется `--reinstall-package`, для обычного `pip` - `--force-reinstall`. После установки выполняется проверка CUDA build; если осталась CPU-сборка, установка считается ошибочной.

Если `requirements.txt` явно закрепляет CPU или другую CUDA-сборку Torch-семейства, скрипт показывает замену в плане и логе:

```text
torch==2.10.0+cpu -> torch==2.10.0+cu128
torchvision==0.25.0+cu126 -> torchvision==0.25.0+cu128
```

Такая замена применяется только к обычным requirement-строкам, где можно безопасно сохранить публичную версию пакета и заменить local-tag wheel.

Прямые ссылки на wheel/URL не переписываются автоматически. Если прямая ссылка указывает на CPU или неподходящую CUDA-сборку Torch, скрипт считает это блокирующим конфликтом: URL может вести на конкретный файл, и безопасно заменить его без участия пользователя нельзя.

При использовании `uv` для Torch дополнительно передается явный backend:

```text
--torch-backend cu128
```

Этот backend добавляется не только к отдельной команде установки `torch`, но и к остальным `uv pip install` командам. Это нужно потому, что обычные пакеты могут транзитивно зависеть от PyTorch и при обновлении иначе способны заменить CUDA-сборку на CPU-сборку.

Для `onnxruntime` действует такое же правило выбора бэкенда: если найдена NVIDIA/CUDA, требование `onnxruntime` преобразуется в установку `onnxruntime-gpu`; для AMD/Intel используется `onnxruntime-directml`; без GPU остается обычный `onnxruntime`. После установки ONNX Runtime проверяется список providers. Для CUDA-сценария ожидается `CUDAExecutionProvider`.

Если имя ONNX Runtime меняется из-за выбранного GPU-бэкенда, это также показывается явно:

```text
onnxruntime>=1.20 -> onnxruntime-gpu>=1.20
```

Для `insightface` больше не применяется принудительный откат на `numpy==1.26.4`. Корневой набор PySM использует `numpy==2.4.6`, совместимый с Python 3.11 и проверенный вместе с InsightFace 1.0.1, OpenCV, ONNX Runtime GPU, SciPy, scikit-image и scikit-learn.

После установки InsightFace скрипт дополнительно проверяет:

* наличие дистрибутива `onnxruntime-gpu`;
* отсутствие одновременно установленного CPU-дистрибутива `onnxruntime`;
* доступность `CUDAExecutionProvider` или `TensorrtExecutionProvider`.

Если любая из проверок не пройдена, категория InsightFace получает статус `FAIL`.

## 5. Параметры

* `inst_search_path`
  * Путь к файлу `requirements.txt` / `pyproject.toml` или к папке, где нужно искать зависимости.
  * По умолчанию используется корневой каталог PySM.
  * Если путь указан явно, но не найден, скрипт завершится ошибкой и не будет переключаться на fallback-путь.

* `inst_python_interpreter`
  * Путь к целевому `python.exe`, куда нужно устанавливать пакеты.
  * По умолчанию используется текущий Python, которым запущен скрипт.
  * Если путь указан явно, но файл не найден, скрипт завершится ошибкой и не будет устанавливать пакеты в другое окружение.

* `inst_upgrade`
  * Принудительно обновляет пакеты, даже если они уже установлены.

* `inst_verbose`
  * Включает подробный лог и traceback при ошибках.

* `inst_analyze_only`
  * Только анализирует GPU/CUDA и завершает работу.
  * Файл зависимостей не ищется, план установки не строится.

* `inst_plan_only`
  * Строит полный план установки, показывает команды, но не устанавливает пакеты.
  * Полезно перед установкой тяжелых библиотек вроде `torch`, `onnxruntime-gpu` и `insightface`.

## 6. Поддержка requirements.txt

Парсер requirements поддерживает:

* обычные зависимости: `package`, `package==1.2.3`, `package[extra]>=1.0`;
* environment markers: `package; python_version >= "3.11"`;
* include-файлы: `-r other.txt`, `--requirement other.txt`;
* constraints: `-c constraints.txt`, `--constraint constraints.txt`;
* pip-options: `--index-url`, `--extra-index-url`, `--find-links`, `--trusted-host`, `--pre`, `--no-index`, `--no-binary`, `--only-binary`;
* прямые ссылки: `package @ https://...`, URL на wheel/архив;
* VCS-ссылки: `git+https://...#egg=package`;
* editable-установки: `-e ./local_package`;
* локальные пути и wheel-файлы;
* перенос строк через `\`;
* UTF-8 файлы с BOM.

Относительные пути в `-r`, `-c`, `--find-links`, локальных wheel и editable-зависимостях резолвятся относительно файла, где они указаны.

Constraints-файлы не только передаются в итоговую команду `uv/pip` через `--constraint`, но и используются в предварительном плане. Если основной `requirements.txt` содержит `numpy`, а `constraints.txt` содержит `numpy==1.26.4`, скрипт проверит установленную версию `numpy` до запуска установки:

```text
[!] Конфликт constraints: требуется ==1.26.4; обновить: numpy (2.0.0 -> 1.26.4)
```

Если constraint уже соблюден, пакет остается в коротком формате:

```text
[OK] Соответствует: numpy (1.26.4)
```

В режиме `inst_upgrade`, если constraint задает точную версию, план показывает переход к этой версии:

```text
[U] Обновить: beautifulsoup4 (4.14.3 -> 4.15.0)
```

Ограничение: `--hash` распознается и не ломает парсинг, но hash-проверка не применяется в категорийном режиме установки, потому что зависимости устанавливаются группами, а не одной командой `pip install -r`.

## 7. Рекомендованный порядок использования

1. Запустить `inst_analyze_only`, чтобы проверить GPU, драйвер и portable CUDA.
2. Запустить `inst_plan_only`, чтобы увидеть выбранные wheel/index-url и команды установки.
3. Если план выглядит корректно, запустить установку без `inst_plan_only`.

Во время установки скрипт не ждет молча завершения `uv`/`pip`: процесс запускается в потоковом режиме, а PySM получает живые обновления progress-bar. В обычный лог попадают команда, результат категории и ошибки; технический поток `uv`/`pip` используется для progress-bar и диагностики.

## 8. Важные ограничения

* Скрипт предназначен для Windows.
* Скрипт не обновляет NVIDIA-драйвер.
* Скрипт не собирает portable CUDA.
* Для CUDA-wheel версия CUDA не должна быть новее той, которую поддерживает драйвер NVIDIA.
* Для InsightFace обязателен рабочий GPU provider ONNX Runtime; CPU-only окружение считается ошибкой.
