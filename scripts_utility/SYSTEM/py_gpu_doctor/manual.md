# Сводная диагностика GPU

## Назначение

Скрипт собирает единый отчёт о текущем Python-окружении, драйвере NVIDIA, физических видеокартах и поддержке CUDA в PyTorch. Он ничего не устанавливает и не меняет настройки системы.

Используйте его:

- перед установкой или обновлением GPU-библиотек;
- если PyTorch не видит видеокарту;
- чтобы сравнить сведения драйвера и Python-окружения;
- при подготовке технического отчёта о рабочем компьютере.

## Что проверяется

1. **Окружение Python и CUDA**
   - версия и путь текущего Python;
   - операционная система;
   - значения `CUDA_PATH` и `PYSM_CUDA_PATH`;
   - путь и версия portable CUDA PySM из `version.json`;
   - наличие `nvidia-smi`, системного `nvcc` и компилятора portable CUDA.
2. **Драйвер и физические GPU через NVML**
   - версия драйвера NVIDIA;
   - максимальная версия CUDA API, поддерживаемая драйвером;
   - модель, память, вычислительная способность, загрузка и температура каждого GPU.
3. **PyTorch**
   - версия PyTorch;
   - CUDA, с которой собрана текущая версия PyTorch;
   - версия cuDNN;
   - доступность CUDA и список устройств с точки зрения PyTorch.
4. **Сопоставление**
   - совпадает ли количество GPU, обнаруженных NVML и PyTorch.

Отсутствие `pynvml` или `torch` не прерывает весь скрипт: доступные разделы всё равно выполняются.

## Запуск

Обычный способ — запустить скрипт из PySM. В этом режиме статусы оформляются тематическими значками из `pysm_icons.py`.

Из командной строки:

```powershell

```

Справка:

```powershell

```

## Как читать отчёт

- **Успех** — проверка выполнена и ожидаемый компонент доступен.
- **Предупреждение** — часть сведений недоступна, но остальные проверки продолжаются.
- **Ошибка** — компонент найден, но не загрузился или не смог выполнить запрос.
- **Информация** — нейтральные сведения об устройстве или пропущенной проверке.

Важно различать три версии CUDA:

- значение драйвера показывает максимальный уровень CUDA API, который поддерживает драйвер;
- системный `nvcc` относится к CUDA Toolkit из `PATH`;
- portable CUDA PySM — отдельный комплект библиотек, который может иметь другую версию;
- `torch.version.cuda` показывает CUDA Runtime, с которой собран PyTorch.

Эти значения не обязаны совпадать. Практическую готовность PyTorch проверяет отдельный скрипт `py_torch_doctor`.

## Типичные результаты

### NVML видит GPU, а PyTorch — нет

Проверьте, что установлен PyTorch с поддержкой CUDA, а не CPU-сборка. Затем проверьте совместимость сборки PyTorch с драйвером NVIDIA.

### `pynvml` не установлен

Системный раздел будет пропущен, но PyTorch всё равно будет проверен. Для NVML-раздела нужен пакет `nvidia-ml-py` в том же Python-окружении.

### `nvcc` не найден

Это не всегда ошибка. Многие готовые сборки PyTorch используют собственный CUDA Runtime и не требуют системный компилятор `nvcc`. Он нужен прежде всего для сборки CUDA-расширений.

### Системный и portable `nvcc` имеют разные версии

Это допустимо: они относятся к разным CUDA Toolkit. Для процессов PySM важен комплект, который фактически добавлен в окружение запуска. Скрипт показывает оба пути, чтобы не смешивать системную и portable установку.

### Количество GPU не совпадает

Проверьте переменную `CUDA_VISIBLE_DEVICES`, настройки контейнера или ограничения запуска процесса. NVML обычно видит физические устройства, а PyTorch может видеть только разрешённую часть.

## Требования и ограничения

- Поддерживается диагностика GPU NVIDIA.
- Для системных сведений нужен драйвер NVIDIA и пакет `nvidia-ml-py`.
- Для раздела PyTorch нужен пакет `torch`.
- Скрипт не проверяет производительность и не запускает длительную нагрузку.
- Скрипт не создаёт отчётные файлы и не изменяет пользовательские данные.
