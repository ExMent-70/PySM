# Общий API кэша изображений PySM

Публичный модуль: `pysm_lib.pysm_image_cache`.

API предназначен для GUI-скриптов, которые показывают фотографии, миниатюры и
производные превью. Он предоставляет:

- автоматическую инвалидацию при изменении исходного файла;
- ограниченный в байтах потокобезопасный LRU-кэш;
- атомарную запись производных изображений;
- загрузку и масштабирование через `QImageReader`;
- асинхронный пул с дедупликацией одинаковых запросов;
- подавление устаревшего результата для одного канала GUI;
- статистику памяти, декодирования и асинхронных запросов.

## Основные классы

- `ImageRequest` описывает исходник, целевой размер, режим масштабирования и
  вариант производного изображения.
- `QtImageCache` выполняет синхронную загрузку `QImage` и обслуживает RAM/disk
  cache.
- `AsyncImageLoader` выполняет загрузку вне GUI-потока и возвращает
  `AsyncImageResult` через сигнал `imageReady`.
- `ByteLRUCache` используется для специфичных производных объектов, размер
  которых может оценить вызывающий код.

## Пример

```python
cache = QtImageCache(
    cache_root,
    memory_limit_bytes=256 * 1024 * 1024,
    disk_limit_bytes=4 * 1024 * 1024 * 1024,
)
loader = AsyncImageLoader(cache, max_threads=4)

loader.imageReady.connect(self._on_image_ready)
loader.request(
    ImageRequest(
        photo_path,
        (320, 240),
        mode="fit",
        variant="my_script.thumbnail.v1",
    ),
    channel=("thumbnail", item_id),
    persist=True,
    disk_format="JPG",
    quality=85,
)
```

Повторный запрос с тем же `channel` делает предыдущий результат устаревшим.
Если старый worker завершится позже, его изображение не будет отправлено в
виджет.

`cancel(channel)` удаляет соответствующий запрос из очереди пула, если он ещё
не начал выполняться, и подавляет результат уже запущенной операции.
`cancel_all()` применяет ту же логику ко всем каналам загрузчика. Если один
физический запрос обслуживает несколько каналов, он сохраняется, пока остаётся
хотя бы один подписчик. После отмены уже выполняющегося запроса такой же файл
можно немедленно запросить снова: новый подписчик не присоединяется к
отменённой задаче.

## Потоки Qt

Общий API декодирует и хранит `QImage`. Создавать `QPixmap`, `QIcon` и изменять
виджеты разрешено только в обработчике `imageReady` на GUI-потоке.

## Ключи и варианты

Ключ учитывает разрешенный путь, `mtime_ns`, `ctime_ns`, размер файла, целевой
размер, режим, автотрансформацию, разрешение увеличения, `variant` и версию
алгоритма. Значение `variant` должно описывать назначение производного файла и
меняться при изменении алгоритма его построения.

Необязательный `crop` задается нормализованным прямоугольником
`(x, y, width, height)` в диапазоне от 0 до 1 и применяется до масштабирования.
Несколько разных crop-запросов одного исходного файла повторно используют один
декодированный `QImage` в пределах общего RAM-бюджета.

`disk_limit_bytes` задает максимальный объем производных файлов. При превышении
лимита удаляются давно не использовавшиеся записи. Поврежденная производная
удаляется и автоматически пересоздается из исходного изображения.

Cache root задает вызывающий скрипт. Разные скрипты могут использовать общий
механизм, но самостоятельно выбирают расположение и политику хранения своих
производных файлов.
